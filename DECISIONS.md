# Decisions

Deviations from the source research specs and the reasons for them. The specs
in `SupportingInformation/` are read-only inputs; this file records where the
implementation consciously differs.

## 1. Dropped the undeclared `remediatedPattern` requirement

The `UXLawCard` schema printed in `Open-Source UX Deck Architecture.md` lists
`remediatedPattern` in `required[]` but never declares it in `properties`. With
`additionalProperties: false`, that makes every record invalid: a required key
cannot be present unless it is declared, and it cannot be absent either.

The card-anatomy section (field 7) defines one anti-pattern/remediation pair,
and `antiPattern` already carries `{ violation, remediation }`. Declaring a
second flat `remediatedPattern` would create two sources of truth for the same
copy. This slice removes `remediatedPattern` from `required[]` and does not
declare it in `properties`. Per the lead's ruling, `antiPattern` stays the
single pair.

## 2. Axiom length is enforced as both characters and words

The schema sets `axiom.maxLength = 110` and describes it as "15 words or
fewer". A character cap does not enforce a word count, and a word count does
not bound glyph width in the printed card. `scripts/validate.mjs` therefore
enforces both: Ajv applies the schema's 110-character limit, and the validator
additionally rejects axioms longer than 15 words. Every current record passes
both.

## 3. Added five `svgShape` values: `convention-grid`, `split-bar`, `paired-panels`, `steering-tunnel`, `decline-curve`

The source enum is `network`, `hierarchy`, `proximity-grid`, `target-vector`,
`decay-curve`. Those five cannot express Jakob's Law, which compares a
conventional layout with a divergent one, so the enum adds `convention-grid`.
Slice 2 adds `split-bar` and `paired-panels` for the decision cards; section 15
gives the reason. Slice 3 adds `steering-tunnel` for Accot-Zhai and
`decline-curve` for Decision Fatigue; sections 21 and 22 give the reasons. The
cards use these values:

every stroke, and `currentColor` for every mark.

## 4. Print imposition is deferred

`packages/prepress` renders one card per page (recto then verso), not a 3x3
SRA3 press-sheet run. The source spec's column-inversion formula and crop-mark
imposition are out of scope for this vertical slice. Consequence: the output
is a review/proof PDF, not a production imposition sheet. A press-sheet engine
will need a larger MediaBox so crop marks can sit outside the bleed, which is
why the current template draws trim ticks inside the bleed band of each
3.00 x 5.00 in page.

## 5. The web viewer uses a generated classic script instead of `fetch`

The viewer must open by double-clicking `packages/web/index.html`, with no
server and no bundler. Browsers block `fetch()` of local JSON from `file://`,
so `scripts/generate-web-data.mjs` bundles the cards and their generated SVG
into `packages/web/deck-data.js` (a classic script executed before `app.js`).
The bundle is deterministic and committed; the JSON in `data/laws/` remains the
only source of truth.

## 6. Print crop marks live inside the bleed band

The brief fixes the PDF page box at 3.00 x 5.00 in (trim plus bleed). Marks
placed outside the bleed would enlarge that box. The template therefore draws
corner trim ticks and a light trim outline at the 2.75 x 4.75 in trim line,
inside the 0.125 in bleed. A production imposition sheet would use a larger
MediaBox and conventional outside-the-bleed marks; that is deferred with the
3x3 engine (see 4).

## 7. The schema `$id` points at the public repository

`data/law-schema.json` uses
`https://raw.githubusercontent.com/tjmustard/knowledge-domain-decks-skills/main/data/law-schema.json`
as its `$id`. This is the canonical location on the repository's default
branch. Validation reads the local file, so the identifier is not fetched; it
becomes a live remote reference only once this slice is merged to `main`. If
the file moves, update the `$id` in the same change.

## 8. Typst is required but absent on this machine

`packages/prepress/build.mjs` checks for `typst` and exits with code 2 and a
clear install message rather than substituting another renderer. When Typst is
available, `npm run build:pdf` emits `packages/prepress/dist/ux-deck.pdf` and
`npm run check:pdf` asserts every MediaBox is 216 x 360 pt.

## 9. One primary source per card (repo-wide rule)

Every card carries exactly one primary paper in `academicOrigin`, with that
paper's own authors, year, title, and venue. Authors and years from different
papers are never merged into one citation. This rule applies to all 52 cards
when the deck expands.

Consequences for this slice:

- `MPA-01` cites Murdock (1962), "The Serial Position Effect of Free Recall",
  *Journal of Experimental Psychology*, 64(5), 482-488. Ebbinghaus (1885) is
  the earlier foundation but is not part of that citation; if it is mentioned
  later, it needs its own prose attribution.
- `DEC-01` is named **Hick's Law**. Its `academicOrigin` cites Hick (1952),
  "On the Rate of Gain of Information", *Quarterly Journal of Experimental
  Psychology*, 4(1), 11-26. The law is also associated with Ray Hyman:
  Hyman (1953), "Stimulus Information as a Determinant of Reaction Time",
  *Journal of Experimental Psychology*, 45(3), 188-196, independently
  replicated the result. The deck cites Hick as the primary source because the
  schema carries one citation per card; Hyman appears in no deck field. The
  card name follows the citation, so a reader who follows the Source line is
  not left looking for a second author.
- The source table's single-origin row ("Serial Position -> Ebbinghaus 1885,
  1913") is superseded by the exact primary paper chosen above.

An optional `additionalSources` field was considered and rejected: it would
reintroduce the merged-citation problem and contradicts the one-source rule.

## 10. SupportingInformation stays out of git in this slice

The six research specs under `SupportingInformation/` are read-only inputs and
are excluded by the committed `.gitignore` (not only by the machine-local
`.git/info/exclude`). Their publication and licensing provenance is the
person's call, so they are not committed. The knowledge they carry enters the
repository through the derived CC0 dataset in `data/laws/` and the citations on
each card. Revisit with the person before publishing anything that depends on
those specs.

## 11. The printed diagram is deliberately monochrome

The parametric diagrams are drawn with `currentColor`, so the web viewer tints
them with the category accent. Typst does not resolve `currentColor` from the
surrounding text fill, so the same SVG prints dark. Rather than ship an
accidental difference, print keeps the diagram monochrome on purpose: at the
1.8 in diagram size it is thin linework, and thin coloured strokes are the
first thing to muddy on a photocopier or a tired office laser. A black diagram
prints and copies correctly, while the card's accent band, rule, category line,
red violation, and green fix keep their colour, so the category still reads at
a glance.

The alternative was to substitute the category hex when writing
`packages/prepress/build/svg/*.svg`. That would add a third accent table - one
already exists in `card.typ` and another in `app.js` - for a diagram that reads
better in black at this size. The web keeps the accent, so the two artifacts
differ deliberately rather than by omission.

What would change this: a colour press run, which the source specification's
CMYK/FOGRA39 workflow anticipates. At that point the diagrams take the category
hue, drawn from one accent source rather than three.

## 12. Tesler's Law cites Saffer, because Tesler has no paper

The source list attributes Tesler's Law to "Larry Tesler (c. 1984), personal
communication; formalized by Dan Saffer (2007), *Designing for Interaction*".
A personal communication has no authors, year, title, or venue that a card's
`academicOrigin` can carry, and inventing one would be a fabricated citation.

`DEC-03` is named **Tesler's Law** and cites Saffer (2007), *Designing for
Interaction*, New Riders, first edition. The card name follows the law's common
name; the citation follows what can be verified. Tesler's 1984 conversation is
recorded here rather than on the card.

The year needed checking rather than copying. The first edition was released on
18 July 2006 and carries a 2007 copyright date; the British National
Bibliography and the Internet Archive both catalogue it as 2007. The card prints
2007 and says "first edition", so a reader who finds a 2006 release date is not
misled about which book is meant.

## 13. Cognitive Friction cites a trade book

The one-primary-source rule prefers canonical academic papers or peer-reviewed
HCI literature. `DEC-07` cites Cooper (1999), *The Inmates Are Running the
Asylum*, Sams Publishing, which is a trade book.

It is kept because Cooper coined the construct there. There is no peer-reviewed
paper that defines "cognitive friction" as a named idea waiting to be cited
instead; substituting a paper that merely overlaps would cite the wrong origin
to satisfy the look of rigour. The card cites the book that named the thing.

## 14. Miller's Law and Working Memory Capacity ship as two cards

The source list carries law 24, Miller's Law (7 ± 2 chunks), and law 28,
Working Memory Capacity Model (about 4 chunks). Both describe working memory
capacity, and the shipped `DEC-02` already states the 7 ± 2 claim, so a second
card risks restating it with a different number.

That risk was put to the project owner, who decided against the lead's
recommendation to drop the second card: every one of the 54 principles gets a
card, and `DEC-06` carries Cowan's revision. **The decision is the owner's, made with the
duplication stated plainly; this entry is the mitigation, not a defence of the
outcome.**

The two cards are given different jobs:

- `DEC-02` keeps Miller: the historical 7 ± 2 figure, chunking as a technique,
  and the interface moves that follow from chunking — group digits, phase the
  form, cap the overview.
- `DEC-06` carries Cowan (2001), "The Magical Number 4 in Short-Term Memory",
  *Behavioral and Brain Sciences*, 24(1), 87-114: the revision to about four
  chunks of novel information in active operational memory, why 7 ± 2 overstates
  what a person can hold while executing a task, and the opposite consequence —
  do not chunk harder, take the burden out of memory entirely, with persistent
  context, sticky headers, visible prior-step values, and copy affordances.

The source list merges two papers in law 28's attribution, Baddeley & Hitch
(1974) and Cowan (2001). Under the one-primary-source rule `DEC-06` cites Cowan
alone, because Cowan carries the four-chunk revision that the card is about;
Baddeley & Hitch are recorded here and appear in no deck field.

If the two cards ever read as one claim, the honest repair is to fold them into
`DEC-02`, not to keep a paraphrase in the deck.

## 15. `split-bar` and `paired-panels` draw what the existing shapes cannot

None of the six existing shapes could draw the six decision cards honestly.
`network` draws a bounded set of chunks, `hierarchy` draws one decision into
branches, `proximity-grid` draws grouping, `target-vector` draws motor distance,
`decay-curve` draws a sequence curve, and `convention-grid` draws a familiar
layout beside a chaotic one. A conserved total that moves between two owners
(Tesler's Law) and a fixed set of demands measured against a capacity line
(Cognitive Load Theory) are both a partition of one track: `split-bar` draws
labelled segments on a fixed track with an optional dashed reference line, so
the total stays visibly constant while the partition moves.

A difference in how many things there are, or the same things under two
descriptions, needs two comparable bodies: `paired-panels` draws two bordered
panels of equal cells with captions. Choice Overload gets nine plans against
three with one marked; Cognitive Friction gets one expected step against five
actual ones at one fixed cell size; Framing gets two identical panel bodies, so
only the caption changes. In each case the geometry carries the claim rather
than the caption alone.

Fill means the outcome the caption names, not decoration. In `split-bar` the
solid segment is the party the row label describes, and in `paired-panels` a
solid cell is one the panel caption counts. That is why the Framing panels are
complements of one ten-cell set, nine solid under "9 IN 10 SURVIVE" and one
under "1 IN 10 DIE", and why the second Tesler row fills the system's share.
Flipping either back to match its sibling would make the caption lie.

Both shapes read every parameter they declare, and neither needs generator
support beyond `renderSvg`: the rules and skill do not read `graphicMetaphor`,
and the web bundle and print build both call the same function. `network`
gained optional label and surplus-text parameters so DEC-06 can print Cowan's
four-chunk capacity; with no overrides, DEC-02 renders byte-identically.

## 16. Nothing checks prose about the artifacts

The gate checks the records, the generators, the web viewer and the print page
boxes. It checks no sentence that describes an artifact. Every false claim
found in review so far - a card count, a page range, a font size, what a
command printed - belongs to that class: the sentence and the artifact are
separate files with no join between them.

The proposed mechanism, recorded here rather than built, is a committed
measurement JSON with the prose generated from it instead of parsed out of
prose. QA settled its shape by testing:

- fields: `typst_version`, `pages`, `bytes`, `smallest_font_pt`, `versos`,
  `worst_overrun_pt`, `paper_before_trim_pt`;
- no digest, because three builds of one commit give the same byte count and
  three different md5s;
- no `build_commit`, because the file would invalidate itself on the next
  commit;
- the measuring script must reproduce both the 12-page build at `931918d` and
  the 24-page build at `5619408` before its output may be committed;
- the scope line says the deck takes Typst's bundled faces rather than the
  machine's, which stays true only while the template names no font family.

The limit is part of the record: this covers numbers, and it never supports
state claims such as "no browser, no Typst". A later mechanism should not be
read as broader than that.

## 17. Decision Fatigue instructs practice, not the depleted-self mechanism

`DEC-11` cites Baumeister et al. (1998), "Ego Depletion: Is the Active Self a
Limited Resource?", *Journal of Personality and Social Psychology*, 74(5),
1252-1265, as the source does. The mechanism that paper proposed did not
survive replication: Hagger et al. (2016), "A Multilab Preregistered Replication
of the Ego-Depletion Effect", *Perspectives on Psychological Science*, 11(4),
546-573.

The lead's decision is to keep the card and change what it asserts. Its axiom
states the observable - decision quality degrades over a long session of
repetitive choices - and not the failed explanation. The trigger describes the
condition (a long run of questions, recent answers left at the default), and
the checklist keeps the source's practices (batch micro-decisions, defer
non-critical configuration, pre-populate safe defaults), because those are good
practice whether or not depletion is the cause. The test applied is wider than
deleting one noun: remove "ego depletion" and every form of the theory, and no
sentence or mark becomes false. No field may imply a depletable resource or a
willpower budget, so the record avoids exhausted, spent, depleted, running-low,
willpower, and self-control-reserve language, and its diagram plots quality
against position in a session rather than drawing a battery, a gauge, or a bar
that empties.

This follows the shape of section 14: a card the research no longer supports as
stated ships because its guidance survives, and the record says what the card
does and does not assert.

## 18. Cognitive Absorption cites Agarwal & Karahanna alone

The source entry merges Csikszentmihalyi (1975), *Beyond Boredom and Anxiety*,
with Agarwal & Karahanna (2000), "Time Flies When You're Having Fun: Cognitive
Absorption and Beliefs about Information Technology Usage", *MIS Quarterly*,
24(4), 665-694. The card is named for the construct the second paper defined
and measured, so it cites that paper alone: temporal dissociation, focused
immersion, heightened enjoyment, control, and curiosity.

Its axiom deliberately differs from the source's law-33 sentence, which
describes challenge-skill balance. That sentence is Csikszentmihalyi's, and it
would have the card instruct what A&K did not measure. The architecture spec's
time-and-motion table already carries a separate Flow Channel Balance row; if
that row gets a card, Csikszentmihalyi is its citation, not this one. Until
then he is the antecedent, recorded here and in no deck field.

## 19. Doherty Threshold cites the technical report

The source gives "The Economic Value of Rapid Response Time" as *IBM Systems
Journal*, 21(2), 149-180. That citation does not resolve: the journal's 21(2)
run is occupied by other articles and the title is not in the issue. The work
is Walter J. Doherty & Ahrvind J. Thadhani, "The Economic Value of Rapid
Response Time", IBM Technical Report GE20-0752-0, White Plains, NY. The card
cites the report and spells the co-author Thadhani, as the report does; some
secondary sources render it Thadani.

The card prints no page count. Shneiderman's 1984 reference list gives the
report as 11 pages and the Computer History Museum records 12, so a page range
would assert a precision the sources do not agree on. The venue string stops at
the report number and place.

Checked at the Computer History Museum catalogue (entry 102751398) and in IBM's
own published copy before the card was written.

## 20. Perceived Performance cites Seow; Miller is the antecedent

The source entry merges Seow (2008), *Designing and Engineering Time: The
Psychology of Time Perception in Software*, Addison-Wesley, with Miller (1968),
"Response Time in Man-Computer Conversational Transactions", *AFIPS Fall Joint
Computer Conference Proceedings*, 267-301. The card is about perceived duration
and progress cues, which is Seow's subject, so it cites Seow alone.

Miller's response-time thresholds are the antecedent and are recorded here, not
on the card. They also sit on the same ground as `TME-03`, so keeping them off
this card keeps the two claims apart.

## 21. `steering-tunnel` draws what the eight existing shapes cannot

`TME-02` is about a pointer travelling through a bounded corridor, not about
acquiring a point target. `target-vector` draws distance and target width at
rest and has no path, so it cannot show that a trip of the same length becomes
harder as the corridor narrows. `steering-tunnel` draws two corridors of equal
length and different width with a pointer path inside each, which is the claim
the card makes.

Every declared parameter is read by the drawing code: `narrowWidth` and
`wideWidth` set the two corridor heights, `length` sets their extent,
`narrowLabel` and `wideLabel` caption them, and `caption` prints the claim. The
schema adds one enum value under the existing object rules, and the rules,
skill, and web generators need no change because none of them inspects
`graphicMetaphor`.

## 22. `decline-curve` draws what `decay-curve` cannot

`DEC-11` plots decision quality against position in a session, so the drawing
has to fall from left to right and stop falling. `decay-curve` cannot serve:
its path returns to the peak at the right end by construction, which draws the
U of serial-position recall, and its four labels are literal recall words.
Giving it a direction parameter would change an existing shape's contract for a
new card's benefit, so `MPA-01` keeps that shape untouched and the decline gets
its own.

`decline-curve` takes `startY`, `endY`, `startLabel`, `endLabel`, and `caption`,
all read by the drawing code. SVG y grows downward, so a decline means
`startY < endY`. Both control points interpolate between the endpoints, which
makes every sampled y move in one direction by construction rather than by
choosing tidy numbers. The shape also carries a `monotoneDown` trait beside its
drawing; the acceptance gate reads that declaration and, only for shapes that
make it, checks that the control points start downward and that twenty evenly
spaced samples never rise. `decay-curve` declares the trait false. The check is
scoped to the claim because a global monotonicity rule would fail `MPA-01`,
whose U-shaped curve is correct.

The diagram is the observable, not the abandoned mechanism: it plots quality
across a session and does not draw a battery, a gauge, or a bar emptying.

## 23. The `split-bar` threshold moved under two published cards

The slice changed `split-bar`, which draws `DEC-03` and `DEC-05` as well as the
new `TME-03`. Row labels moved from centred above each track to its left edge,
and the threshold is now drawn per bar — a tick above the first bar and one
vertical dashed segment through each bar — instead of a single rule spanning
the whole drawing. The single rule at 400 ms struck through the segment labels
that sit below each track and through the row label above the first, which
TME-03 made obvious. `DEC-03` and `DEC-05` were re-rendered and inspected after
the change: the party fills and the 85 capacity line still land on the tracks
their labels name. This is a correction to a shared shape, not a revert, and it
is recorded so a reader comparing the published cards against the current
output finds the reason beside the other shape notes.

## 24. A sentence-ending title keeps its own stop, in three expressions

The Source line appended a period unconditionally, so a title ending in "?"
printed a doubled stop. `DEC-11`'s title exposed it ("Limited Resource?."), but
the general rule was fixed rather than the instance: suppress the added stop
when the title already ends in `?`, `!` or `.`, the convention Chicago and MLA
both use. The general form caught `DEC-04` immediately — "Good Thing?." was
wrong in the same build and nobody had noticed — which is the argument for
fixing the rule.

It was four surfaces, not one: the card (`packages/prepress/src/card.typ`), the
web viewer (`packages/web/app.js`), and the two generated artifacts
(`packages/rules/generate.mjs`), where the same field is rendered with no
publication after it. A dead `formatCitation` in `scripts/lib/deck.mjs` carried
the same bug and was deleted rather than fixed, because dead code with a live
bug is how the bug returns. The other sixteen cards' source lines were shown
unchanged by a text diff of the two builds.

The rule now exists as three expressions, because the languages cannot share
code without a build step: an inline conditional in Typst, and the same
`/[.?!]$/` test in the two JavaScript renderers. They agree today. Two limits
are recorded with it.

The first is the duplication itself. The trigger to act early is: if any one of
the three expressions changes before the formatter slice lands, change all
three. The planned remedy is the one in §16's direction - compute `titleStop`
and `authorsLabel` once in `scripts/lib/deck.mjs`, emit them into both
generated bundles, and let each renderer print a value instead of
re-implementing a rule.

The second is that the rule tests the last character, so a title ending in a
closing quote still takes the added stop. Measured rather than reasoned: with
`DEC-11`'s title changed to end `Resource?"` in a scratch worktree and rebuilt,
the PDF prints `Resource?".` and the JavaScript predicate returns false for the
same string, so both renderers give the same wrong answer. No card in the deck
ends that way, so neither limit is a defect in today's output; this entry
exists so the first card that does is recognised as a known edge rather than
rediscovered.

## 25. Citation strings are computed once and printed, not re-derived

The stop fix left the same rule written three times (§24). This slice removes
the duplication: `scripts/lib/deck.mjs` owns `authorsLabel` and `titleStop`,
and both bundles — the one Typst reads and `packages/web/deck-data.js` — carry
the computed strings inside `academicOrigin`. The card template, the viewer,
and both rules artifacts print those fields; none of them joins authors or
tests a character. A renderer that starts computing either again has broken
the slice.

House style joins authors with one ampersand before the last name and commas
between the rest, with no serial comma, using full given names as the records
carry them: two authors print "A & B", three or more print "A, B, C & D".
Six cards change on output because their authors were previously joined with
plain commas: `DEC-04` Iyengar & Lepper, `DEC-08` Tversky & Kahneman, `DEC-10`
Agarwal & Karahanna, `DEC-11` Baumeister, Bratslavsky, Muraven & Tice, `TME-02`
Accot & Zhai, and `TME-03` Doherty & Thadhani. `DEC-11` is the acceptance case:
exactly one ampersand and no ", &".

The stop predicate strips trailing closers (`"`, the curly double quotes,
the apostrophe in both forms, `)`, `]`) before testing for `?`, `!` or `.`, so
a title quoted or parenthesised as a whole is judged by its own final stop
while possessives and mid-title apostrophes are unaffected. The acceptance gate
runs twelve named cases against this commit's `deck.mjs`, including all the
forms §24 recorded as the edge it could not yet handle. No schema changes: the
two fields are computed into the bundles, not written into `data/laws/*.json`.

`authorsLabel` stays plain text with ordinary spaces, so the generated markdown
and both bundles can be grepped and diffed for " & " without hidden characters.
The printed card is the one surface where the ampersand could end a line
(`DEC-11`'s acceptance line did), so the template, not the shared field, binds
it to the surname with U+00A0 at render time. The no-break is a typographic
decision local to print; the viewer needs it only if its own text wraps there.
This keeps one citation string across the deck while letting each surface
apply its own line-breaking rule.

Two limits travel with the check. Its artifact list is hard-coded to the same
three files the generator layer targets — `packages/web/deck-data.js`,
`rules/ux-rules.md` and `skills/ux-laws/SKILL.md` — so a fourth generated
artifact would have to be added in both places, and the gate cannot tell you
that only one list grew; whoever touches either list should be looking at the
other. And the failure message names a byte offset: that locates the character
for whoever maintains the check, but means little in a CI line, so a line
number or the nearest citation would read better if it is ever revised.

The check does not assert that the no-break works, only that the shared field
stays plain. The evidence that the printed ampersand is no longer line-final
is a rendered page, which is what `print: contents` would cover if it had a
text layer; a string comparison cannot see a line break, so that assertion
belongs with the print layer, not here.

## 26. The axiom and the citation move together

Where a card's canonical attribution names more than one work, or names a
collaborator the work itself does not, the verse cites the single work whose
statement the axiom expresses. The card's name and this file carry the rest.
A printed Source line is a claim about what a book says, so a lineage the cited
work does not contain is the same false attribution the one-primary-source rule
exists to prevent. Laws 40, 41, 42 and 43 apply the rule.

**Law 40, Weber-Fechner.** The Repository names Weber (1834), *De Pulsu,
Resorptione, Auditu et Tactu*, and Fechner (1860), *Elemente der Psychophysik*.
The card cites Weber alone, because the axiom — a just-noticeable difference is
a ratio of the starting magnitude — is Weber's statement, not Fechner's
logarithmic scale. Read in the e-rara scan of the 1834 edition (ETH-Bibliothek
Zürich, DOI 10.3931/e-rara-70261): the title page reads *De Pulsu, Resorptione,
Auditu et Tactu. Annotationes Anatomicae et Physiologicae. Auctore Ernesto
Henrico Weber ... Lipsiae, prost... C. F. Koehler. 1834*. At pp. 172-173, in the
*Summa doctrinae de tactu*, Weber writes that in comparing things *non
differentiam rerum, sed rationem differentiae ad magnitudinem rerum inter se
comparatarum percipimus*, with difference thresholds of about 1/15 or 1/30 for
lifted weights, 1/100 for line lengths, and 1/320 for tone frequencies.
Fechner's log form and his 1860 book are the later formalisation. Listing both
men as authors of a card neither co-wrote would print the collaboration as a
fact. The placement is the weaker of this file's two cross-category notes: the
JND is a perceptual ratio law rather than a timing law, and the source's
sectioning is the only thing holding it in Time, Motion & Ergonomics.

**Law 41, Gilbreth.** The Repository's attribution names Frank and Lillian
Gilbreth. The 1911 Van Nostrand title page names Frank Bunker Gilbreth alone:
*Motion Study: A Method for Increasing the Efficiency of the Workman / by Frank
B. Gilbreth ... with an introduction by Robert Thurston Kent*. The Internet
Archive scan and the Wellcome catalogue both carry one author. **This card
corrects the Repository.** The "& Gilbreth" is a later customary attribution,
not this edition's authorship. Lillian Gilbreth collaborated with Frank from
around 1907, is credited on their later joint works, and her solo *Psychology of
Management* (1914) is the more directly relevant book to this subject, though it
is not the one cited here. Naming her on a title page that does not carry her
would be the same error in the other direction.

**Law 42, Crossman and Welford.** The Repository names Crossman (1956),
formalised by Welford (1968). The card cites Welford, *Fundamentals of Skill*
(Methuen, London, 1968), because the axiom and the diagram print Welford's
index, MT = a + b log2(A/W + 0.5). Read at ch. V, "Movement", pp. 145-160: p. 147
gives the equation and credits Crossman's suggested error-correction for target
width, and the added 0.5 keeps the index finite as distance approaches width.
Crossman (1956) is not a journal article but an unpublished University of
Birmingham PhD thesis, *The measurement of perceptual load in manual
operations* (WorldCat OCLC 55953230); its index is log2(D/W), without the 0.5,
so it is not the formula on the card. The velocity-adjusts-to-width-to-prevent-
overshoot framing belongs to the iterative-corrections account in Crossman &
Goodeve (1963, published 1983), not to the 1956 thesis, and is not printed. Two
consequences follow: the originating name is not the printed source because the
card prints the formula and the formula is Welford's; and the lineage the card
name carries stops at Crossman, where the index begins. The name also drops the
Repository's "Movement": "Crossman's Movement Velocity Law (Welford's Variant)"
is 52 characters and the schema caps names at 50, so this departure is forced
by the cap rather than chosen. "Velocity" still names the claim, and the Welford
parenthetical lineage is intact.

**Law 43, Dodge.** The Repository names Dodge (1900) and Rayner (1998). The card
cites Dodge alone. Read in the Zenodo scan of the article (DOI
10.1037/h0067215): *Psychological Review* 7(5), 454-465; at p. 456 Dodge reports
that the eyes are "never in motion" in a mirror, at p. 457 that words in the
middle of a fixated line are illegible while the eye travels, and at p. 464 that
eye movements are "very short, for movements of 10° certainly not more than 60
σ, and possibly less than half that". Rayner's 1998 review is the later
synthesis and is not printed. This is a motion card rather than an attention
card because it measures the timing of a movement and what that movement does
to the incoming field — the same subject as target acquisition and steering. It
makes no claim about what attention selects. The card prints no durations:
Dodge gives only the under-60 ms bound at p. 464, so the Repository's 200-300 ms
fixation and 30-50 ms saccade figures are not printed. A diagram prints a number
only when the cited work reports it — the same discipline that removed the
performance counts from DEC-11's diagram.

Three other names shorten the Repository by house style and fit the 50-character
cap — Keystroke-Level Model drops "(KLM-GOMS)", Gilbreth Motion Economy drops
"Principles", and Weber-Fechner JND Law compresses "of Just Noticeable
Difference (JND)" — as distinct from TME-09's forced trim.

Newell & Rosenbloom's chapter is chapter 1 of the 1981 Erlbaum edition,
conventionally pp. 1-55; one bibliography gives 1-56, a one-page disagreement in
the literature. The 2013 Psychology Press reissue carries it as chapter 6 with
different pagination - Crossref records pp. 12-66 under DOI
10.4324/9780203728178-6 - so a range taken from that volume does not locate the
chapter in the book the card cites. The card therefore prints no page range, the
same rule §19 applied to the Doherty report's extent.

## 27. Five shapes for the motion cards, and one reused

None of the ten existing shapes draws these claims, so this slice adds five and
reuses `split-bar` for the keystroke model. Every parameter listed here is read
by `scripts/svg.js`; the acceptance gate perturbs each leaf and fails if the
drawing does not change.

- `power-curve` (TME-05) draws a fall that is steep early and flat late.
  `decline-curve` is monotone but its two control points interpolate at fixed
  fractions, so it cannot bend that way. The new shape moves both control points
  early and declares `monotoneDown: true`, so the gate samples this path as it
  samples `DEC-11`'s.
- `split-bar` (TME-06) is reused: the keystroke model is one track partitioned
  into labelled operator durations, which is what the shape already draws.
- `ratio-scale` (TME-07) puts the same four values on two axes, one spaced by
  value and one by ratio, because the claim is about spacing rather than about
  a curve. No existing shape compares two scalings.
- `reach-map` (TME-08) draws a phone outline, a target in the thumb zone, a
  target in the far corner, and the travel each costs. No existing shape encodes
  a route.
- `difficulty-line` (TME-09) plots movement time against the index of
  difficulty. `target-vector` draws two targets and hard-codes Fitts's formula,
  which is a different index and cannot be relabelled without changing TME-01.
- `scan-path` (TME-10) alternates dwell points and the gaps between them; no
  existing shape draws fixations and saccades.

The five names are in the schema's `svgShape` enum, and the deck now has fifteen
shapes across twenty-four cards. QA measured the label margins on the six new
cards at card size; the tightest are SHORT REACH at 0.25 pt, NARROW TARGET at
0.50 pt and THUMB ZONE at 0.79 pt. The 45-character safe-box bound was measured
on `decline-curve` and has not been re-measured on these geometries, so
lengthening any label on the five new shapes needs a fresh measurement first.

## 28. A rename moves two pages, and a byte delta cannot see it

Three things learned while checking this slice's last commits, all of them about
the instrument rather than the card:

- A card's name is printed twice: in the recto's title band and in the verso's
  header. Renaming TME-07 changed pages 41 and 42, not page 41 alone. A check
  that watched only rectos would have reported half the change and called it the
  whole one.
- The PDF's length moved by 16 bytes between two builds, which is inside the
  run-to-run noise and therefore says nothing about whether a page changed.
  Rendering all 48 pages and hashing the images is what showed exactly two
  differences.
- That noise has a cause: Typst writes `/ModDate` on every compile, so two builds
  of one commit differ by 100 bytes - the timestamp and the trailer `/ID` derived
  from it. That is why the byte delta was unreadable, and why page hashes are the
  right instrument today. If `SOURCE_DATE_EPOCH` is set later, byte comparison
  becomes valid again, and that change is what would make this note outdated.
  It is set now, by `packages/prepress/build.mjs`; §29 records the choice, and
  byte comparison is valid again.

## 29. A fixed epoch, not the commit time

Typst writes `/ModDate` and the XMP dates on every compile and derives the
trailer `/ID` from them, so an unpinned build is only reproducible up to those
four fields. `packages/prepress/build.mjs` now passes `SOURCE_DATE_EPOCH`, the
reproducible-builds convention, and the PDF joins the ruleset, skill and web
bundle in regenerating byte-identically.

Three decisions in that change:

- **A fixed date, not the commit timestamp.** `git log -1 --format=%ct` would
  make the stamp meaningful - the time the source was committed - but it needs a
  git checkout. An exported tree or tarball has no history, and a build there
  must still work and must produce the same bytes as a build in a checkout. The
  cost is that `/ModDate` reads 2026-11-09T00:00:00Z for every build, whenever it
  is made; the README says so rather than implying the file records its build
  time.
- **An inherited `SOURCE_DATE_EPOCH` wins.** A distributor who repackages the
  deck can stamp their own date, as the convention intends. A value that is not
  whole seconds, or is too large to survive JavaScript's integer precision
  (`999999999999999999999` is digits before `Number()` turns it into `1e21`),
  exits 2 instead of falling back, so a bad value cannot produce a file that
  quietly claims the deck's epoch or a renderer error that blames Typst.
- **Proven by effect, not by assumption.** Two builds with the pin are
  byte-identical at 579,849 bytes. Two direct `typst compile` runs without it
  differ in `/ModDate`, the XMP dates and `/ID` while both being 579,859 bytes,
  which is why the byte count never exposed the difference. A third build with
  `SOURCE_DATE_EPOCH=0` is distinct from both, so the epoch is the variable at
  work and not a coincidence of timing. A build from `git archive` in a
  directory with no `.git` produced the same 579,849 bytes, so the reason for
  choosing a fixed date over the commit time is measured rather than argued.

What this does not prove: identical bytes across Typst versions, or across
machines while the diagram labels resolve a monospace stack against the host's
fonts. The claim is per version and per font environment until that font is
pinned, which is queued as its own change.

One case is disclosed rather than bounded: a safe integer far out of range
(9007199254740991) passes this check and Typst rejects it with "creation
timestamp is out of range", exit 1. That failure is accurate and non-zero, and
a bound here would be a second definition of what Typst accepts, which would
drift on the next version bump.


## 30. Six cards for memory and attention, and what each source can carry

The research list's memory section runs 44-54. This slice writes six of its
eleven cards: laws 44, 46, 47, 48, 49 and 50. Law 45 is the Serial Position
Effect, already published as MPA-01. Von Restorff, Peak-End, Anchoring and
Broadbent were confirmed against Crossref (title, authors, volume, pages, DOI)
before the records were written; two need more than a record:

- **Zeigarnik has no DOI of its own, and the card prints none.** Crossref holds
  no record of the 1927 original. The only item under her name for this work is
  the 1938 Ellis translation (10.1037/11496-025), which is not the original and is
  not cited; the year, journal, title and volume were read from that translation's
  title page, not from the paper. A Crossref record at Psychologische Forschung 9,
  pp. 1-85 (10.1007/BF02409755) looks like the original by volume and pages, but
  its title is the series' - "Untersuchungen zur Handlungs- und
  Affektpsychologie" - and its author is Kurt Lewin. It is a container-level entry
  for Lewin's series as published in that volume: it names the editor of the
  series, not the contributor. Attaching it to her paper would mean deciding
  whose article occupies those pages, which is the guessing this deck avoids. It
  also explains why the pages appear to match: 1-85 are the series' opening
  pages, which her paper occupies.
- **Confirmation Bias corrects the Repository.** The Repository pairs a broad
  axiom - operators prefer confirming information and dismiss disconfirming
  signals - with Wason's 2-4-6 task, which demonstrates one failure of hypothesis
  testing but does not state the broad claim. This card keeps the broad axiom and
  cites Nickerson (1998), the review that states it; Wason remains named here as
  the origin of the paradigm and the reason he is not the printed source. The
  operator accepted a review in `academicOrigin` as the cost of printing the
  broad claim rather than the narrow demonstration.

**An ID is a stable key, not a position.** MPA-02 is law 44 while MPA-01 is law
45, and DEC-11 is law 31 while DEC-09 is law 32, because Decision Fatigue was
restored after being dropped. One rule, two instances: an id is never renumbered
to follow the source order.

Four shapes are new because none of the fifteen existing ones draws the claim:
`odd-one-out` sets one mark apart in a field of uniform neighbours
(`proximity-grid` varies spacing, not the item); `peak-end-curve` marks the peak
and the ending and draws no average (`decay-curve` is a U-shaped serial-position
curve and would be read as the same claim); `anchor-line` puts an initial mark and
later estimates on one value axis (`target-vector` draws distance and width);
`filter-gate` passes one of several channels through a barrier (`network` draws
nodes and edges). Two are reused: `paired-panels` compares recall across two
conditions for Zeigarnik, and `split-bar` partitions one budget of attention for
Confirmation Bias.

Every label on the new arrangements was measured at card size against the
generated SVG, in the Menlo face the print build embeds, and every bounding box
lies inside the 400 x 400 box. The tightest clearances are EVEN SPLIT at 1.92 pt
from the reference line, END at 2.49 pt from its dot, and DISTINCT at 3.78 pt from
the odd mark. The longest is 41 characters at 221.9 units, inside the
45-character, 248-unit bound measured on `decline-curve`. The pending font pin
will re-derive all of these, so none is a permanent bound.

## 31. Prefer the instrument that fails loudly

A check must fail on the condition it cannot see, not return a plausible answer.
Four instruments this session failed silently: a grep pattern that could not
match the shape it searched for; a request to "check" a work that was not
retrievable, where the check was recall; a 16-byte PDF delta read as a change
against 100 bytes of timestamp noise; and a raw.githubusercontent branch URL
serving a cached file while the commit URL already carried the new one. None of
them threw. When a check can be wrong without saying so, make it assert something
it can only satisfy by looking, and report what it could not establish instead of
reporting nothing found.
