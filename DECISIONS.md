# Decisions

Deviations from the source research specs and the reasons for them. The specs
in `SupportingInformation/` are read-only inputs; this file records where the
implementation consciously differs.

## 1. Dropped the undeclared `remediatedPattern` requirement

The `UXLawCard` schema printed in `Open-Source UX Deck Architecture.md` lists
`remediatedPattern` in `required[]` but never declares it in `properties`. With
`additionalProperties: false`, that makes every record invalid: a required key
cannot be present unless it is declared, and it cannot be absent either.

The card-anatomy section (field 7) defines one anti-pattern/remediation pair,
and `antiPattern` already carries `{ violation, remediation }`. Declaring a
second flat `remediatedPattern` would create two sources of truth for the same
copy. This slice removes `remediatedPattern` from `required[]` and does not
declare it in `properties`. Per the lead's ruling, `antiPattern` stays the
single pair.

## 2. Axiom length is enforced as both characters and words

The schema sets `axiom.maxLength = 110` and describes it as "15 words or
fewer". A character cap does not enforce a word count, and a word count does
not bound glyph width in the printed card. `scripts/validate.mjs` therefore
enforces both: Ajv applies the schema's 110-character limit, and the validator
additionally rejects axioms longer than 15 words. Every current record passes
both.

## 3. Added five `svgShape` values: `convention-grid`, `split-bar`, `paired-panels`, `steering-tunnel`, `decline-curve`

The source enum is `network`, `hierarchy`, `proximity-grid`, `target-vector`,
`decay-curve`. Those five cannot express Jakob's Law, which compares a
conventional layout with a divergent one, so the enum adds `convention-grid`.
Slice 2 adds `split-bar` and `paired-panels` for the decision cards; section 15
gives the reason. Slice 3 adds `steering-tunnel` for Accot-Zhai and
`decline-curve` for Decision Fatigue; sections 21 and 22 give the reasons. The
cards use these values:

every stroke, and `currentColor` for every mark.

## 4. Print imposition is deferred

`packages/prepress` renders one card per page (recto then verso), not a 3x3
SRA3 press-sheet run. The source spec's column-inversion formula and crop-mark
imposition are out of scope for this vertical slice. Consequence: the output
is a review/proof PDF, not a production imposition sheet. A press-sheet engine
will need a larger MediaBox so crop marks can sit outside the bleed, which is
why the current template draws trim ticks inside the bleed band of each
3.00 x 5.00 in page.

## 5. The web viewer uses a generated classic script instead of `fetch`

The viewer must open by double-clicking `packages/web/index.html`, with no
server and no bundler. Browsers block `fetch()` of local JSON from `file://`,
so `scripts/generate-web-data.mjs` bundles the cards and their generated SVG
into `packages/web/deck-data.js` (a classic script executed before `app.js`).
The bundle is deterministic and committed; the JSON in `data/laws/` remains the
only source of truth.

## 6. Print crop marks live inside the bleed band

The brief fixes the PDF page box at 3.00 x 5.00 in (trim plus bleed). Marks
placed outside the bleed would enlarge that box. The template therefore draws
corner trim ticks and a light trim outline at the 2.75 x 4.75 in trim line,
inside the 0.125 in bleed. A production imposition sheet would use a larger
MediaBox and conventional outside-the-bleed marks; that is deferred with the
3x3 engine (see 4).

## 7. The schema `$id` points at the public repository

`data/law-schema.json` uses
`https://raw.githubusercontent.com/tjmustard/knowledge-domain-decks-skills/main/data/law-schema.json`
as its `$id`. This is the canonical location on the repository's default
branch. Validation reads the local file, so the identifier is not fetched; it
becomes a live remote reference only once this slice is merged to `main`. If
the file moves, update the `$id` in the same change.

## 8. Typst is required but absent on this machine

`packages/prepress/build.mjs` checks for `typst` and exits with code 2 and a
clear install message rather than substituting another renderer. When Typst is
available, `npm run build:pdf` emits `packages/prepress/dist/ux-deck.pdf` and
`npm run check:pdf` asserts every MediaBox is 216 x 360 pt.

## 9. One primary source per card (repo-wide rule)

Every card carries exactly one primary paper in `academicOrigin`, with that
paper's own authors, year, title, and venue. Authors and years from different
papers are never merged into one citation. This rule applies to all 52 cards
when the deck expands.

Consequences for this slice:

- `MPA-01` cites Murdock (1962), "The Serial Position Effect of Free Recall",
  *Journal of Experimental Psychology*, 64(5), 482-488. Ebbinghaus (1885) is
  the earlier foundation but is not part of that citation; if it is mentioned
  later, it needs its own prose attribution.
- `DEC-01` is named **Hick's Law**. Its `academicOrigin` cites Hick (1952),
  "On the Rate of Gain of Information", *Quarterly Journal of Experimental
  Psychology*, 4(1), 11-26. The law is also associated with Ray Hyman:
  Hyman (1953), "Stimulus Information as a Determinant of Reaction Time",
  *Journal of Experimental Psychology*, 45(3), 188-196, independently
  replicated the result. The deck cites Hick as the primary source because the
  schema carries one citation per card; Hyman appears in no deck field. The
  card name follows the citation, so a reader who follows the Source line is
  not left looking for a second author.
- The source table's single-origin row ("Serial Position -> Ebbinghaus 1885,
  1913") is superseded by the exact primary paper chosen above.

An optional `additionalSources` field was considered and rejected: it would
reintroduce the merged-citation problem and contradicts the one-source rule.

## 10. SupportingInformation stays out of git in this slice

The six research specs under `SupportingInformation/` are read-only inputs and
are excluded by the committed `.gitignore` (not only by the machine-local
`.git/info/exclude`). Their publication and licensing provenance is the
person's call, so they are not committed. The knowledge they carry enters the
repository through the derived CC0 dataset in `data/laws/` and the citations on
each card. Revisit with the person before publishing anything that depends on
those specs.

## 11. The printed diagram is deliberately monochrome

The parametric diagrams are drawn with `currentColor`, so the web viewer tints
them with the category accent. Typst does not resolve `currentColor` from the
surrounding text fill, so the same SVG prints dark. Rather than ship an
accidental difference, print keeps the diagram monochrome on purpose: at the
1.8 in diagram size it is thin linework, and thin coloured strokes are the
first thing to muddy on a photocopier or a tired office laser. A black diagram
prints and copies correctly, while the card's accent band, rule, category line,
red violation, and green fix keep their colour, so the category still reads at
a glance.

The alternative was to substitute the category hex when writing
`packages/prepress/build/svg/*.svg`. That would add a third accent table - one
already exists in `card.typ` and another in `app.js` - for a diagram that reads
better in black at this size. The web keeps the accent, so the two artifacts
differ deliberately rather than by omission.

What would change this: a colour press run, which the source specification's
CMYK/FOGRA39 workflow anticipates. At that point the diagrams take the category
hue, drawn from one accent source rather than three.

## 12. Tesler's Law cites Saffer, because Tesler has no paper

The source list attributes Tesler's Law to "Larry Tesler (c. 1984), personal
communication; formalized by Dan Saffer (2007), *Designing for Interaction*".
A personal communication has no authors, year, title, or venue that a card's
`academicOrigin` can carry, and inventing one would be a fabricated citation.

`DEC-03` is named **Tesler's Law** and cites Saffer (2007), *Designing for
Interaction*, New Riders, first edition. The card name follows the law's common
name; the citation follows what can be verified. Tesler's 1984 conversation is
recorded here rather than on the card.

The year needed checking rather than copying. The first edition was released on
18 July 2006 and carries a 2007 copyright date; the British National
Bibliography and the Internet Archive both catalogue it as 2007. The card prints
2007 and says "first edition", so a reader who finds a 2006 release date is not
misled about which book is meant.

## 13. Cognitive Friction cites a trade book

The one-primary-source rule prefers canonical academic papers or peer-reviewed
HCI literature. `DEC-07` cites Cooper (1999), *The Inmates Are Running the
Asylum*, Sams Publishing, which is a trade book.

It is kept because Cooper coined the construct there. There is no peer-reviewed
paper that defines "cognitive friction" as a named idea waiting to be cited
instead; substituting a paper that merely overlaps would cite the wrong origin
to satisfy the look of rigour. The card cites the book that named the thing.

## 14. Miller's Law and Working Memory Capacity ship as two cards

The source list carries law 24, Miller's Law (7 ± 2 chunks), and law 28,
Working Memory Capacity Model (about 4 chunks). Both describe working memory
capacity, and the shipped `DEC-02` already states the 7 ± 2 claim, so a second
card risks restating it with a different number.

That risk was put to the project owner, who decided against the lead's
recommendation to drop the second card: every one of the 54 principles gets a
card, and `DEC-06` carries Cowan's revision. **The decision is the owner's, made with the
duplication stated plainly; this entry is the mitigation, not a defence of the
outcome.**

The two cards are given different jobs:

- `DEC-02` keeps Miller: the historical 7 ± 2 figure, chunking as a technique,
  and the interface moves that follow from chunking — group digits, phase the
  form, cap the overview.
- `DEC-06` carries Cowan (2001), "The Magical Number 4 in Short-Term Memory",
  *Behavioral and Brain Sciences*, 24(1), 87-114: the revision to about four
  chunks of novel information in active operational memory, why 7 ± 2 overstates
  what a person can hold while executing a task, and the opposite consequence —
  do not chunk harder, take the burden out of memory entirely, with persistent
  context, sticky headers, visible prior-step values, and copy affordances.

The source list merges two papers in law 28's attribution, Baddeley & Hitch
(1974) and Cowan (2001). Under the one-primary-source rule `DEC-06` cites Cowan
alone, because Cowan carries the four-chunk revision that the card is about;
Baddeley & Hitch are recorded here and appear in no deck field.

If the two cards ever read as one claim, the honest repair is to fold them into
`DEC-02`, not to keep a paraphrase in the deck.

## 15. `split-bar` and `paired-panels` draw what the existing shapes cannot

None of the six existing shapes could draw the six decision cards honestly.
`network` draws a bounded set of chunks, `hierarchy` draws one decision into
branches, `proximity-grid` draws grouping, `target-vector` draws motor distance,
`decay-curve` draws a sequence curve, and `convention-grid` draws a familiar
layout beside a chaotic one. A conserved total that moves between two owners
(Tesler's Law) and a fixed set of demands measured against a capacity line
(Cognitive Load Theory) are both a partition of one track: `split-bar` draws
labelled segments on a fixed track with an optional dashed reference line, so
the total stays visibly constant while the partition moves.

A difference in how many things there are, or the same things under two
descriptions, needs two comparable bodies: `paired-panels` draws two bordered
panels of equal cells with captions. Choice Overload gets nine plans against
three with one marked; Cognitive Friction gets one expected step against five
actual ones at one fixed cell size; Framing gets two identical panel bodies, so
only the caption changes. In each case the geometry carries the claim rather
than the caption alone.

Fill means the outcome the caption names, not decoration. In `split-bar` the
solid segment is the party the row label describes, and in `paired-panels` a
solid cell is one the panel caption counts. That is why the Framing panels are
complements of one ten-cell set, nine solid under "9 IN 10 SURVIVE" and one
under "1 IN 10 DIE", and why the second Tesler row fills the system's share.
Flipping either back to match its sibling would make the caption lie.

Both shapes read every parameter they declare, and neither needs generator
support beyond `renderSvg`: the rules and skill do not read `graphicMetaphor`,
and the web bundle and print build both call the same function. `network`
gained optional label and surplus-text parameters so DEC-06 can print Cowan's
four-chunk capacity; with no overrides, DEC-02 renders byte-identically.

## 16. Nothing checks prose about the artifacts

The gate checks the records, the generators, the web viewer and the print page
boxes. It checks no sentence that describes an artifact. Every false claim
found in review so far - a card count, a page range, a font size, what a
command printed - belongs to that class: the sentence and the artifact are
separate files with no join between them.

The proposed mechanism, recorded here rather than built, is a committed
measurement JSON with the prose generated from it instead of parsed out of
prose. QA settled its shape by testing:

- fields: `typst_version`, `pages`, `bytes`, `smallest_font_pt`, `versos`,
  `worst_overrun_pt`, `paper_before_trim_pt`;
- no digest, because three builds of one commit give the same byte count and
  three different md5s;
- no `build_commit`, because the file would invalidate itself on the next
  commit;
- the measuring script must reproduce both the 12-page build at `931918d` and
  the 24-page build at `5619408` before its output may be committed;
- the scope line says the deck takes Typst's bundled faces rather than the
  machine's, which stays true only while the template names no font family.

The limit is part of the record: this covers numbers, and it never supports
state claims such as "no browser, no Typst". A later mechanism should not be
read as broader than that.

## 17. Decision Fatigue instructs practice, not the depleted-self mechanism

`DEC-11` cites Baumeister et al. (1998), "Ego Depletion: Is the Active Self a
Limited Resource?", *Journal of Personality and Social Psychology*, 74(5),
1252-1265, as the source does. The mechanism that paper proposed did not
survive replication: Hagger et al. (2016), "A Multilab Preregistered Replication
of the Ego-Depletion Effect", *Perspectives on Psychological Science*, 11(4),
546-573.

The lead's decision is to keep the card and change what it asserts. Its axiom
states the observable - decision quality degrades over a long session of
repetitive choices - and not the failed explanation. The trigger describes the
condition (a long run of questions, recent answers left at the default), and
the checklist keeps the source's practices (batch micro-decisions, defer
non-critical configuration, pre-populate safe defaults), because those are good
practice whether or not depletion is the cause. The test applied is wider than
deleting one noun: remove "ego depletion" and every form of the theory, and no
sentence or mark becomes false. No field may imply a depletable resource or a
willpower budget, so the record avoids exhausted, spent, depleted, running-low,
willpower, and self-control-reserve language, and its diagram plots quality
against position in a session rather than drawing a battery, a gauge, or a bar
that empties.

This follows the shape of section 14: a card the research no longer supports as
stated ships because its guidance survives, and the record says what the card
does and does not assert.

## 18. Cognitive Absorption cites Agarwal & Karahanna alone

The source entry merges Csikszentmihalyi (1975), *Beyond Boredom and Anxiety*,
with Agarwal & Karahanna (2000), "Time Flies When You're Having Fun: Cognitive
Absorption and Beliefs about Information Technology Usage", *MIS Quarterly*,
24(4), 665-694. The card is named for the construct the second paper defined
and measured, so it cites that paper alone: temporal dissociation, focused
immersion, heightened enjoyment, control, and curiosity.

Its axiom deliberately differs from the source's law-33 sentence, which
describes challenge-skill balance. That sentence is Csikszentmihalyi's, and it
would have the card instruct what A&K did not measure. The architecture spec's
time-and-motion table already carries a separate Flow Channel Balance row; if
that row gets a card, Csikszentmihalyi is its citation, not this one. Until
then he is the antecedent, recorded here and in no deck field.

## 19. Doherty Threshold cites the technical report

The source gives "The Economic Value of Rapid Response Time" as *IBM Systems
Journal*, 21(2), 149-180. That citation does not resolve: the journal's 21(2)
run is occupied by other articles and the title is not in the issue. The work
is Walter J. Doherty & Ahrvind J. Thadhani, "The Economic Value of Rapid
Response Time", IBM Technical Report GE20-0752-0, White Plains, NY. The card
cites the report and spells the co-author Thadhani, as the report does; some
secondary sources render it Thadani.

The card prints no page count. Shneiderman's 1984 reference list gives the
report as 11 pages and the Computer History Museum records 12, so a page range
would assert a precision the sources do not agree on. The venue string stops at
the report number and place.

Checked at the Computer History Museum catalogue (entry 102751398) and in IBM's
own published copy before the card was written.

## 20. Perceived Performance cites Seow; Miller is the antecedent

The source entry merges Seow (2008), *Designing and Engineering Time: The
Psychology of Time Perception in Software*, Addison-Wesley, with Miller (1968),
"Response Time in Man-Computer Conversational Transactions", *AFIPS Fall Joint
Computer Conference Proceedings*, 267-301. The card is about perceived duration
and progress cues, which is Seow's subject, so it cites Seow alone.

Miller's response-time thresholds are the antecedent and are recorded here, not
on the card. They also sit on the same ground as `TME-03`, so keeping them off
this card keeps the two claims apart.

## 21. `steering-tunnel` draws what the eight existing shapes cannot

`TME-02` is about a pointer travelling through a bounded corridor, not about
acquiring a point target. `target-vector` draws distance and target width at
rest and has no path, so it cannot show that a trip of the same length becomes
harder as the corridor narrows. `steering-tunnel` draws two corridors of equal
length and different width with a pointer path inside each, which is the claim
the card makes.

Every declared parameter is read by the drawing code: `narrowWidth` and
`wideWidth` set the two corridor heights, `length` sets their extent,
`narrowLabel` and `wideLabel` caption them, and `caption` prints the claim. The
schema adds one enum value under the existing object rules, and the rules,
skill, and web generators need no change because none of them inspects
`graphicMetaphor`.

## 22. `decline-curve` draws what `decay-curve` cannot

`DEC-11` plots decision quality against position in a session, so the drawing
has to fall from left to right and stop falling. `decay-curve` cannot serve:
its path returns to the peak at the right end by construction, which draws the
U of serial-position recall, and its four labels are literal recall words.
Giving it a direction parameter would change an existing shape's contract for a
new card's benefit, so `MPA-01` keeps that shape untouched and the decline gets
its own.

`decline-curve` takes `startY`, `endY`, `startLabel`, `endLabel`, and `caption`,
all read by the drawing code. SVG y grows downward, so a decline means
`startY < endY`. Both control points interpolate between the endpoints, which
makes every sampled y move in one direction by construction rather than by
choosing tidy numbers. The shape also carries a `monotoneDown` trait beside its
drawing; the acceptance gate reads that declaration and, only for shapes that
make it, checks that the control points start downward and that twenty evenly
spaced samples never rise. `decay-curve` declares the trait false. The check is
scoped to the claim because a global monotonicity rule would fail `MPA-01`,
whose U-shaped curve is correct.

The diagram is the observable, not the abandoned mechanism: it plots quality
across a session and does not draw a battery, a gauge, or a bar emptying.

## 23. The `split-bar` threshold moved under two published cards

The slice changed `split-bar`, which draws `DEC-03` and `DEC-05` as well as the
new `TME-03`. Row labels moved from centred above each track to its left edge,
and the threshold is now drawn per bar — a tick above the first bar and one
vertical dashed segment through each bar — instead of a single rule spanning
the whole drawing. The single rule at 400 ms struck through the segment labels
that sit below each track and through the row label above the first, which
TME-03 made obvious. `DEC-03` and `DEC-05` were re-rendered and inspected after
the change: the party fills and the 85 capacity line still land on the tracks
their labels name. This is a correction to a shared shape, not a revert, and it
is recorded so a reader comparing the published cards against the current
output finds the reason beside the other shape notes.

## 24. A sentence-ending title keeps its own stop, in three expressions

The Source line appended a period unconditionally, so a title ending in "?"
printed a doubled stop. `DEC-11`'s title exposed it ("Limited Resource?."), but
the general rule was fixed rather than the instance: suppress the added stop
when the title already ends in `?`, `!` or `.`, the convention Chicago and MLA
both use. The general form caught `DEC-04` immediately — "Good Thing?." was
wrong in the same build and nobody had noticed — which is the argument for
fixing the rule.

It was four surfaces, not one: the card (`packages/prepress/src/card.typ`), the
web viewer (`packages/web/app.js`), and the two generated artifacts
(`packages/rules/generate.mjs`), where the same field is rendered with no
publication after it. A dead `formatCitation` in `scripts/lib/deck.mjs` carried
the same bug and was deleted rather than fixed, because dead code with a live
bug is how the bug returns. The other sixteen cards' source lines were shown
unchanged by a text diff of the two builds.

The rule now exists as three expressions, because the languages cannot share
code without a build step: an inline conditional in Typst, and the same
`/[.?!]$/` test in the two JavaScript renderers. They agree today. Two limits
are recorded with it.

The first is the duplication itself. The trigger to act early is: if any one of
the three expressions changes before the formatter slice lands, change all
three. The planned remedy is the one in §16's direction - compute `titleStop`
and `authorsLabel` once in `scripts/lib/deck.mjs`, emit them into both
generated bundles, and let each renderer print a value instead of
re-implementing a rule.

The second is that the rule tests the last character, so a title ending in a
closing quote still takes the added stop. Measured rather than reasoned: with
`DEC-11`'s title changed to end `Resource?"` in a scratch worktree and rebuilt,
the PDF prints `Resource?".` and the JavaScript predicate returns false for the
same string, so both renderers give the same wrong answer. No card in the deck
ends that way, so neither limit is a defect in today's output; this entry
exists so the first card that does is recognised as a known edge rather than
rediscovered.

## 25. Citation strings are computed once and printed, not re-derived

The stop fix left the same rule written three times (§24). This slice removes
the duplication: `scripts/lib/deck.mjs` owns `authorsLabel` and `titleStop`,
and both bundles — the one Typst reads and `packages/web/deck-data.js` — carry
the computed strings inside `academicOrigin`. The card template, the viewer,
and both rules artifacts print those fields; none of them joins authors or
tests a character. A renderer that starts computing either again has broken
the slice.

House style joins authors with one ampersand before the last name and commas
between the rest, with no serial comma, using full given names as the records
carry them: two authors print "A & B", three or more print "A, B, C & D".
Six cards change on output because their authors were previously joined with
plain commas: `DEC-04` Iyengar & Lepper, `DEC-08` Tversky & Kahneman, `DEC-10`
Agarwal & Karahanna, `DEC-11` Baumeister, Bratslavsky, Muraven & Tice, `TME-02`
Accot & Zhai, and `TME-03` Doherty & Thadhani. `DEC-11` is the acceptance case:
exactly one ampersand and no ", &".

The stop predicate strips trailing closers (`"`, the curly double quotes,
the apostrophe in both forms, `)`, `]`) before testing for `?`, `!` or `.`, so
a title quoted or parenthesised as a whole is judged by its own final stop
while possessives and mid-title apostrophes are unaffected. The acceptance gate
runs twelve named cases against this commit's `deck.mjs`, including all the
forms §24 recorded as the edge it could not yet handle. No schema changes: the
two fields are computed into the bundles, not written into `data/laws/*.json`.

`authorsLabel` stays plain text with ordinary spaces, so the generated markdown
and both bundles can be grepped and diffed for " & " without hidden characters.
The printed card is the one surface where the ampersand could end a line
(`DEC-11`'s acceptance line did), so the template, not the shared field, binds
it to the surname with U+00A0 at render time. The no-break is a typographic
decision local to print; the viewer needs it only if its own text wraps there.
This keeps one citation string across the deck while letting each surface
apply its own line-breaking rule.

Two limits travel with the check. Its artifact list is hard-coded to the same
three files the generator layer targets — `packages/web/deck-data.js`,
`rules/ux-rules.md` and `skills/ux-laws/SKILL.md` — so a fourth generated
artifact would have to be added in both places, and the gate cannot tell you
that only one list grew; whoever touches either list should be looking at the
other. And the failure message names a byte offset: that locates the character
for whoever maintains the check, but means little in a CI line, so a line
number or the nearest citation would read better if it is ever revised.

The check does not assert that the no-break works, only that the shared field
stays plain. The evidence that the printed ampersand is no longer line-final
is a rendered page, which is what `print: contents` would cover if it had a
text layer; a string comparison cannot see a line break, so that assertion
belongs with the print layer, not here.

## 26. The axiom and the citation move together

Where a card's canonical attribution names more than one work, or names a
collaborator the work itself does not, the verse cites the single work whose
statement the axiom expresses. The card's name and this file carry the rest.
A printed Source line is a claim about what a book says, so a lineage the cited
work does not contain is the same false attribution the one-primary-source rule
exists to prevent. Laws 40, 41, 42 and 43 apply the rule.

**Law 40, Weber-Fechner.** The Repository names Weber (1834), *De Pulsu,
Resorptione, Auditu et Tactu*, and Fechner (1860), *Elemente der Psychophysik*.
The card cites Weber alone, because the axiom — a just-noticeable difference is
a ratio of the starting magnitude — is Weber's statement, not Fechner's
logarithmic scale. Read in the e-rara scan of the 1834 edition (ETH-Bibliothek
Zürich, DOI 10.3931/e-rara-70261): the title page reads *De Pulsu, Resorptione,
Auditu et Tactu. Annotationes Anatomicae et Physiologicae. Auctore Ernesto
Henrico Weber ... Lipsiae, prost... C. F. Koehler. 1834*. At pp. 172-173, in the
*Summa doctrinae de tactu*, Weber writes that in comparing things *non
differentiam rerum, sed rationem differentiae ad magnitudinem rerum inter se
comparatarum percipimus*, with difference thresholds of about 1/15 or 1/30 for
lifted weights, 1/100 for line lengths, and 1/320 for tone frequencies.
Fechner's log form and his 1860 book are the later formalisation. Listing both
men as authors of a card neither co-wrote would print the collaboration as a
fact. The placement is the weaker of this file's two cross-category notes: the
JND is a perceptual ratio law rather than a timing law, and the source's
sectioning is the only thing holding it in Time, Motion & Ergonomics.

**Law 41, Gilbreth.** The Repository's attribution names Frank and Lillian
Gilbreth. The 1911 Van Nostrand title page names Frank Bunker Gilbreth alone:
*Motion Study: A Method for Increasing the Efficiency of the Workman / by Frank
B. Gilbreth ... with an introduction by Robert Thurston Kent*. The Internet
Archive scan and the Wellcome catalogue both carry one author. **This card
corrects the Repository.** The "& Gilbreth" is a later customary attribution,
not this edition's authorship. Lillian Gilbreth collaborated with Frank from
around 1907, is credited on their later joint works, and her solo *Psychology of
Management* (1914) is the more directly relevant book to this subject, though it
is not the one cited here. Naming her on a title page that does not carry her
would be the same error in the other direction.

**Law 42, Crossman and Welford.** The Repository names Crossman (1956),
formalised by Welford (1968). The card cites Welford, *Fundamentals of Skill*
(Methuen, London, 1968), because the axiom and the diagram print Welford's
index, MT = a + b log2(A/W + 0.5). Read at ch. V, "Movement", pp. 145-160: p. 147
gives the equation and credits Crossman's suggested error-correction for target
width, and the added 0.5 keeps the index finite as distance approaches width.
Crossman (1956) is not a journal article but an unpublished University of
Birmingham PhD thesis, *The measurement of perceptual load in manual
operations* (WorldCat OCLC 55953230); its index is log2(D/W), without the 0.5,
so it is not the formula on the card. The velocity-adjusts-to-width-to-prevent-
overshoot framing belongs to the iterative-corrections account in Crossman &
Goodeve (1963, published 1983), not to the 1956 thesis, and is not printed. Two
consequences follow: the originating name is not the printed source because the
card prints the formula and the formula is Welford's; and the lineage the card
name carries stops at Crossman, where the index begins. The name also drops the
Repository's "Movement": "Crossman's Movement Velocity Law (Welford's Variant)"
is 52 characters and the schema caps names at 50, so this departure is forced
by the cap rather than chosen. "Velocity" still names the claim, and the Welford
parenthetical lineage is intact.

**Law 43, Dodge.** The Repository names Dodge (1900) and Rayner (1998). The card
cites Dodge alone. Read in the Zenodo scan of the article (DOI
10.1037/h0067215): *Psychological Review* 7(5), 454-465; at p. 456 Dodge reports
that the eyes are "never in motion" in a mirror, at p. 457 that words in the
middle of a fixated line are illegible while the eye travels, and at p. 464 that
eye movements are "very short, for movements of 10° certainly not more than 60
σ, and possibly less than half that". Rayner's 1998 review is the later
synthesis and is not printed. This is a motion card rather than an attention
card because it measures the timing of a movement and what that movement does
to the incoming field — the same subject as target acquisition and steering. It
makes no claim about what attention selects. The card prints no durations:
Dodge gives only the under-60 ms bound at p. 464, so the Repository's 200-300 ms
fixation and 30-50 ms saccade figures are not printed. A diagram prints a number
only when the cited work reports it — the same discipline that removed the
performance counts from DEC-11's diagram.

Three other names shorten the Repository by house style and fit the 50-character
cap — Keystroke-Level Model drops "(KLM-GOMS)", Gilbreth Motion Economy drops

Newell & Rosenbloom's chapter is chapter 1 of the 1981 Erlbaum edition,

## 28. A rename moves two pages, and a byte delta cannot see it

Three things learned while checking this slice's last commits, all of them about
the instrument rather than the card:

- A card's name is printed twice: in the recto's title band and in the verso's
  header. Renaming TME-07 changed pages 41 and 42, not page 41 alone. A check
  that watched only rectos would have reported half the change and called it the
  whole one.
- The PDF's length moved by 16 bytes between two builds, which is inside the
  run-to-run noise and therefore says nothing about whether a page changed.
  Rendering all 48 pages and hashing the images is what showed exactly two
  differences.
- That noise has a cause: Typst writes `/ModDate` on every compile, so two builds
  of one commit differ by 100 bytes - the timestamp and the trailer `/ID` derived
  from it. That is why the byte delta was unreadable, and why page hashes are the
  right instrument today. If `SOURCE_DATE_EPOCH` is set later, byte comparison
  becomes valid again, and that change is what would make this note outdated.
  It is set now, by `packages/prepress/build.mjs`; §29 records the choice, and
  byte comparison is valid again.

## 29. A fixed epoch, not the commit time

Typst writes `/ModDate` and the XMP dates on every compile and derives the
trailer `/ID` from them, so an unpinned build is only reproducible up to those
four fields. `packages/prepress/build.mjs` now passes `SOURCE_DATE_EPOCH`, the
reproducible-builds convention, and the PDF joins the ruleset, skill and web
bundle in regenerating byte-identically.

Three decisions in that change:

- **A fixed date, not the commit timestamp.** `git log -1 --format=%ct` would
  make the stamp meaningful - the time the source was committed - but it needs a
  git checkout. An exported tree or tarball has no history, and a build there
  must still work and must produce the same bytes as a build in a checkout. The
  cost is that `/ModDate` reads 2026-11-09T00:00:00Z for every build, whenever it
  is made; the README says so rather than implying the file records its build
  time.
- **An inherited `SOURCE_DATE_EPOCH` wins.** A distributor who repackages the
  deck can stamp their own date, as the convention intends. A value that is not
  whole seconds, or is too large to survive JavaScript's integer precision
  (`999999999999999999999` is digits before `Number()` turns it into `1e21`),
  exits 2 instead of falling back, so a bad value cannot produce a file that
  quietly claims the deck's epoch or a renderer error that blames Typst.
- **Proven by effect, not by assumption.** Two builds with the pin are
  byte-identical at 579,849 bytes. Two direct `typst compile` runs without it
  differ in `/ModDate`, the XMP dates and `/ID` while both being 579,859 bytes,
  which is why the byte count never exposed the difference. A third build with
  `SOURCE_DATE_EPOCH=0` is distinct from both, so the epoch is the variable at
  work and not a coincidence of timing. A build from `git archive` in a
  directory with no `.git` produced the same 579,849 bytes, so the reason for
  choosing a fixed date over the commit time is measured rather than argued.

What this does not prove: identical bytes across Typst versions, or across
machines while the diagram labels resolve a monospace stack against the host's
fonts. The claim is per version and per font environment until that font is
pinned, which is queued as its own change.

One case is disclosed rather than bounded: a safe integer far out of range
(9007199254740991) passes this check and Typst rejects it with "creation
timestamp is out of range", exit 1. That failure is accurate and non-zero, and
a bound here would be a second definition of what Typst accepts, which would
drift on the next version bump.


## 30. Six cards for memory and attention, and what each source can carry

The research list's memory section runs 44-54. This slice writes six of its
eleven cards: laws 44, 46, 47, 48, 49 and 50. Law 45 is the Serial Position
Effect, already published as MPA-01. Von Restorff, Peak-End, Anchoring and
Broadbent were confirmed against Crossref (title, authors, volume, pages, DOI)
before the records were written; three need more than a record:

- **Zeigarnik has no DOI of its own, and the card prints none.** Crossref holds
  no record of the 1927 original. The only item under her name for this work is
  the 1938 Ellis translation (10.1037/11496-025), which is not the original and is
  not cited; the year, journal, title and volume were read from that translation's
  title page, not from the paper. A Crossref record at Psychologische Forschung 9,
  pp. 1-85 (10.1007/BF02409755) looks like the original by volume and pages, but
  its title is the series' - "Untersuchungen zur Handlungs- und
  Affektpsychologie" - and its author is Kurt Lewin. It is a container-level entry
  for Lewin's series as published in that volume: it names the editor of the
  series, not the contributor. Attaching it to her paper would mean deciding
  whose article occupies those pages, which is the guessing this deck avoids. It
  also explains why the pages appear to match: 1-85 are the series' opening
  pages, which her paper occupies.
- **Confirmation Bias corrects the Repository.** The Repository pairs a broad
  axiom - operators prefer confirming information and dismiss disconfirming
  signals - with Wason's 2-4-6 task, which demonstrates one failure of hypothesis
  testing but does not state the broad claim. This card keeps the broad axiom and
  cites Nickerson (1998), the review that states it; Wason remains named here as
  the origin of the paradigm and the reason he is not the printed source. The
  operator accepted a review in `academicOrigin` as the cost of printing the
  broad claim rather than the narrow demonstration.
- **Selective Attention asserts the observable, not any one mechanism.** The
  first axiom stated that attention filters the rest "before meaning is
  extracted", which is Broadbent's early-selection model. Three accounts compete
  and the deck does not choose between them: Broadbent (1958) selects before
  meaning on the physical channel; Treisman's attenuation model puts the filter
  in the same place but turns unattended channels down rather than off, which is
  why a listener catches their own name; Deutsch & Deutsch (1963) move selection
  after meaning, so every channel is analysed and attention decides what reaches
  awareness. The card prints what all three agree on - one channel is admitted at
  a time and unattended channels are retained only in fragments - so Treisman's
  finding is an instance of the axiom rather than a counterexample to it.
  Broadbent remains the printed source as the origin of the bottleneck account;
  one channel passing a gate is true of all three models, so the shape and the
  gate stay. The diagram carried the same mechanism claim and no longer does: the
  unattended channels used to end in a cross past the gate, a hard block the
  demonstration does not show, and now run on past it thinner and fainter,
  ending in a hollow dot - present, but weak. They stay solid rather than dashed
  because a dash already means a reference or a limit in this deck, on the
  `split-bar` thresholds and the `reach-map` thumb zone, and in a schematic it
  more often reads as absent or projected, which is the claim being removed. The
  caption changed with them, from "the rest are filtered" to "one channel passes;
  the others arrive weakened", because it was the second place the card argued
  with itself. The word and the mark differ on purpose: "fragments" is a metaphor
  for how little survives, not a description of the stroke, because the drawing
  shows quantity - one channel at full strength, two faint - and asserts no
  mechanism at all. If a reader ever takes the picture literally and reads the
  solid line as a whole message getting through, the fix is the word rather than
  the mark. Same shape as DEC-11, which asserts the observable and
  leaves the ego-depletion mechanism in the prose.

**An ID is a stable key, not a position.** MPA-02 is law 44 while MPA-01 is law
45, and DEC-11 is law 31 while DEC-09 is law 32, because Decision Fatigue was
restored after being dropped. One rule, two instances: an id is never renumbered
to follow the source order.

Four shapes are new because none of the fifteen existing ones draws the claim:

(`proximity-grid` varies spacing, not the item); `peak-end-curve` marks the peak

## 31. Prefer the instrument that fails loudly

A check must fail on the condition it cannot see, not return a plausible answer.
Four instruments this session failed silently: a grep pattern that could not
match the shape it searched for; a request to "check" a work that was not
retrievable, where the check was recall; a 16-byte PDF delta read as a change
against 100 bytes of timestamp noise; and a raw.githubusercontent branch URL
serving a cached file while the commit URL already carried the new one. None of
them threw. When a check can be wrong without saying so, make it assert something
it can only satisfy by looking, and report what it could not establish instead of
reporting nothing found.

## 32. A card is one argument

A card states one claim in five places: the axiom, the diagram, the caption, the
trigger and the checklist. A change to any of them re-opens the other four, so an
axiom edit is not finished until all five have been read together against the new
claim - axiom first, then the drawing and its caption, then what triggers the
card and what the checklist tells the reader to do. Selective Attention is the
evidence: the axiom moved to what all three attention models agree on, and the
diagram was left asserting Broadbent's elimination through the caption ("the rest
are filtered") and two crosses past the gate. For one build the card argued with
itself, and each half passed every check - the schema measures the axiom's
length, the page measures the block's fit, and no artifact states that the two
describe the same question. The gate cannot catch a card that disagrees with
itself, and no check can be written to: disagreement between a sentence and a
drawing is not a property either one can be inspected for alone. Re-reading the
five is the step, and it is a person's.

## 33. The schema limit is not a page-fit guarantee

The axiom's `maxLength` is 110 characters, and this page takes fewer. Both
figures below were measured by compiling the string in the real template at the
real 9 pt italic in the 171 pt column, but only one of them is in the history.
The 86-character axiom is the committed one and sets to two lines. The 4.29 pt
overrun describes a rejected draft: a 91-character axiom built in the working
tree, never committed, which the operator replaced before it could be. No commit
in this history overruns its safe box. The arithmetic is what carries the point -
that draft's third line costs 11.66 pt against 7.36 pt of slack, which is how it
would have put the trigger's bottom ink past the 22.5 pt floor. Those are two
points on one page, not a bound. Wrapping
depends on where the spaces fall, not on how many characters there are, so the
only way to know whether a new axiom fits is to compile it in the real column;
the character count is a warning that it might not. Width also depends on the
face and the measure, which is the same reason the 45-character label bound on
`decline-curve` is re-derived whenever the font changes (§30). A future
axiom-length check should therefore warn to re-measure, not decide, and the
decision stays with the rendered page.

## 35. The skill is an index, and the cards are resource files

`skills/ux-laws/SKILL.md` was 28,023 bytes with thirty-four cards: the whole
file loads before an agent has read a line of the code it is auditing, and it
grows by about 800 bytes per card. A skill's cost is paid on every session that
triggers it, so the deck's growth was a tax on the tool meant to help.

The generator now writes an index and five resource files, one per category,
under `skills/ux-laws/resources/`. The index carries the frontmatter, the rules
that hold across every card, and a table per category of ID, name and the card's
own `trigger` sentence - the field that exists to answer "does this card apply
here?". The bodies (axiom, checklist, anti-pattern pair, source) live in the
resource file for their category. Measured on the thirty-four-card deck: the
index is 6,222 bytes and the largest resource file is 9,530 bytes, against
28,023 for the single file before. An agent auditing forms reads `SKILL.md` and
then `resources/decision-making-cognitive-load.md`. `rules/ux-rules.md` stays
whole because it is pasted into a prompt rather than loaded as a skill.

What this costs, stated rather than hidden: the agent must choose a file, and a
wrong choice is a card it never sees. The tables make the choice from the card's
own trigger rather than from its name, and the index says to load several
resources when the change spans categories. A future card whose trigger is too
vague to separate it from its neighbours is now a routing defect as well as a
content one, which is a reason to keep triggers specific.

The description drops "or long lists". No card covers long lists, and a
description is a promise the body has to keep; the split is the change that made
the promise visible. `scripts/accept.mjs` reads the resource files from disk for
its committed-bytes and generator checks, so a category added later is checked
without editing the gate.

## 36. A checklist item says whether code can check it

The skill audit's first finding was that the deck told an agent to do things an
agent cannot do: test recall a day later, measure time-on-task, record every
experimental run. An agent following the file could only skip them silently or
claim them, and nothing in the data let it tell the two kinds of instruction
apart. The card was written for a person who could run the study; the skill is
loaded by a process that cannot.

A checklist item is therefore an object: `text` as before, plus `kind`, either
`code` or `research`. Six of the 113 items are `research`: MPA-02's recall test,
MPA-05's anchored-estimate comparison, MPA-07's two process instructions, MPA-09's
framing test, and TME-05's time-on-task measurement. Everything else is an
instruction a reader of code can act on, including TME-06's keystroke count, which
is an analysis of an interaction path rather than a study. The generated agent
artifacts print the research items with a note that they are not checkable from
code, so an agent can report the gap instead of fabricating a pass.

The print surface does not change. The card prints the same 113 sentences in the
same order, and the PDF is byte-identical to the build before the change - 68
pages, 743,518 bytes, md5 `6292e2e8` - which is the evidence that this is a data
change and not a layout change. Deliberate: the card is held by a person who may
well run the experiment, and adding a mark to six bullets across six cards would
change their fit for a distinction only the agent surface needs. What this leaves
open is that a person reading the printed card still sees one checkbox style for
both kinds; if that matters later, it is a print change with its own measurement.

### The vertical fit of a recto, measured

The recto holds four text elements: the title, the axiom, the figure and the
trigger. Three cards in this commit were first built with their last trigger
line below the bottom safe edge, because a long name wraps and the trigger
then has no room. The check is therefore a measurement of the built page, not
a formula: every card is rendered and its lowest ink read before it is
committed.

Measured on the fifty-four rectos of the deck as this commit leaves it. `T` is
title lines at 14 pt, `A` axiom lines at 9 pt, `B` trigger lines at 7 pt
*below* the "WHEN TO APPLY" label - the label itself, the card id and the
running head are not counted. Bottom ink is the lowest point of the text's
glyph outlines in points from the paper edge, inside the page frame (x 20 to
196 pt, y 15 to 345 pt); the frame rule at 8.83 pt and the vertical rules at
x 9 and 207 are excluded, so this is ink inside the frame, not ink on the
page. The column is read from Typst's SVG export, which emits every glyph as
an outline path: exact geometry that needs neither dpi nor a luminance
threshold. Every recto is within the 22.5 pt safe edge; the topmost outline on
every recto stands at 337.58 to 337.59, 0.08 to 0.09 pt above the 337.5 safe
top, a constant of the template present on the 81e39b7 baseline.

The fifteen cards at `T=2, A=2, B=2` are the tight band. Eight share the lowest
outline, 29.822 pt (+7.32): DEC-06, DEC-09, GES-07, HMM-05, HMM-06, HMM-11,

Four instruments read the same line differently:

    VECTOR OUTLINE  29.822 (g)  29.850 (p)  29.864 (y)   exact path geometry, no grid
    GLYPH BOX       +0.007                              pypdfium, per-glyph metric
    LINE BOX        -0.056, constant per line           PyMuPDF, carries the font's descent
    RASTER INK      quantised to 1/dpi                  864 dpi cannot resolve a 0.042 pt band

A table that puts a line box and a glyph box in one column, under one heading,
is comparing two things and calling it a measurement. The first version of
this table quoted a 864 dpi raster without naming its dpi, threshold or row
convention; its values were multiples of 1/12 pt - 29.75 is row 357, 29.8333
row 358, 31.3333 row 376 - and its grouping was a property of the grid, which
a 0.042 pt band cannot survive. The floor is load-bearing: g's outline, 29.822,
is 357.864 rows and floors to 357, while p's 29.850 (358.200) and y's 29.864
(358.368) floor to 358, which is where the 7/5 split comes from; rounded
rather than floored, all twelve collapse onto row 358 and the split
disappears. The column is now the vector outline, which has no grid.

The four groups are separated by exactly the three line pitches, so the
measurement yields the model the operator derived independently from PyMuPDF
text boxes. It predicts the last line's glyph box, not rendered ink:

    bottom box = 38.74 − 18.13(T − 1) − 11.66(A − 2) − 9.16(B − 3)

Rendered ink sits at or above the box by the descender depth of the last
glyph, 0.05 to 1.7 pt; TME-05's box is 36.24 and its outline 37.879. The raster
agrees with the box to 0.01 pt at 864 dpi and threshold 245, and reads 0.08 pt
higher at threshold 200. Its reference is HMM-01, `T1 A2 B3`, which is in the
deck and measures 38.824 by outline (38.83 at 864 dpi, threshold 245; 38.90 at
threshold 200; 40.5
baseline), against the model's 38.74: a residual of 0.08 to 0.16 on the
reference itself. Every
prediction inherits that residual, so it is printed rather than assumed away.
The relation reproduces the lowest ink of every group to 0.06 pt; every other
card in a group measures 0.08 to 1.7 pt higher, which is the descender range,
not noise to be minimised. Predicting a baseline instead of a box or ink
shifts every value by about 1.73 pt, and the two models are both right about
different quantities - which is why a condition has to name its unit and its
edge.

The two inputs are nearly proportional: one title line costs 18.13 and two
trigger lines 18.32, 0.19 pt apart. That near-coincidence is why a miscount of
`T` or `B` was easy to hide, but the coefficients are separately identified:
three of the four `T` and `B` combinations remain in the deck, and the fourth,
`T2 B3`, was measured before the fix on the overflowing HMM-07 (box 20.61, ink
22.33) and was removed by the trigger cut that made the card fit. Each group
was exact to 0.01, so the relation is not over-parameterised. On the card it
exists to catch, HMM-07's old counts give box 20.61 and the instruments
measured ink 22.33 - a 1.72 pt descender gap, the largest in the deck but the
same quantity. The values 18.13, 11.66 and 9.16 are line spacing, not design
constants. An
earlier statement of this relation rounded them to 18, 11.66 and 9 and counted
`B` as all 7 pt lines on the page, which put the reference two lines out and
evaluated the overflowing HMM-07 to 38.75. That rule passed a card two
instruments placed 0.17 to 0.20 pt below the bottom safe edge. A budget form
written `<= 0` would still pass it: the deck's only card at a zero budget is
the one that failed. The correction is not a coefficient: it is that the page
is measured. An intermediate reading held that the model's reference case did
not occur in the deck; that was an artefact of the same mis-counted `B`, not a
property of the model, and the reference HMM-01 does occur.

So the rule this deck keeps is the measurement: a card fits when its rendered
bottom ink is at or above 22.5 pt, read per card before its commit. The four
coefficient groups above are the observation that makes the table checkable,
not a gate.

Two triggers were shortened to two lines each rather than restyle the card.
HMM-05 lost its third example, "a toggle changes a setting elsewhere". HMM-06
lost the count "three services" and the word "field", keeping both halves of
its trigger: the rejection of valid input and the divergence downstream.
HMM-07 lost its third line, from "Options and edge-case branches pile up" to a
statement that names the main path as the thing nobody can describe. Each card
still says when to apply its law. If the type sizes change, the table must be
measured again.

### What each new shape draws that the other shapes do not

`model-projection` (HMM-02): two domains and the correspondence between them,
which is the card's claim. `network` draws one bounded set of nodes, `hierarchy`
a branching tree, `proximity-grid` distance inside one field; none draws an
expectation in one plane landing - or failing to land - on a state in another.
The mismatched line stops at the plane and the system's unclaimed state is drawn
faded beside it. The drawing encodes no magnitude: four pairs, one mismatch,
chosen to be legible, not measured.

`shared-grammar` (HMM-03): the same header, body and action composition repeated
inside three differently shaped containers. `convention-grid` compares a
familiar layout with a divergent one and `paired-panels` compares two sets of
cells; neither shows one internal grammar surviving a change of container, which
is what integrity means. No magnitude is encoded.

`alignment-pair` (HMM-04): the same rows once snapped to a shared grid and once
nudged off it. The two panels differ in alignment, not in where the parts are
(as `convention-grid` does) and not in quantity (as `split-bar` does). The
drawing shows polish and not the perception of usability; the caption carries
the claim, because the effect is a judgment the drawing cannot make. The offsets
are fixed values, not a measured jitter.

`promise-line` (HMM-05): a stated path and a delivered path from the same
control. `default-fork` draws two options from one point and `anchor-line` a
baseline with estimates above it; neither draws what a label promises against
what the control does. The bow of the solid curve is a drawing decision, not a
measured deviation, and the caption does not turn it into one.

`intake-funnel` (HMM-06): many input shapes converging into one output block.
`filter-gate` removes inputs and `network` connects nodes; neither shows varied
forms normalised into one canonical form. It encodes no ratio: three input
forms, chosen for legibility; a single output box, because the card's claim is
that the output is one form. The first drawing had three output boxes, so it
showed one output form three times under a caption saying "EMIT ONE", which
invites a reader to count three outputs - the opposite of the card. The output count was fixed after that was found, and the
output stack was centred on the funnel's throat. The record also declared
`variants`, which the shape clamps to its three glyph templates: it could not
change the drawing at its own declared value, the gate failed it, and it is
removed rather than propped up with a fourth template that would exist only to
satisfy the check.

`parsimony-path` (HMM-07): two routes between the same two points, one of them
with every detour the other lacks. `difficulty-line` plots time against an
index, `steering-tunnel` draws corridors; neither draws route complexity between
identical endpoints. The detours are not a count of anything; the caption says
"parts", and the drawing does not claim that the shortest route is the best
design.

`org-mirror` (HMM-08): two chains of linked boxes, one for the teams and one for
the product's screens, with dashed lines joining each box to its counterpart.
`network` draws one set of nodes and `hierarchy` one tree; neither draws two
structures and asserts that one is the shape of the other. The dashed joins are
a claim about correspondence, not a measured connection.

`intent-gap` (HMM-09): an intent, a system box, and two arrows each broken by
the gap they cross. `promise-line` draws a path that diverges from its promise;
nothing else draws a path that fails to complete. The gap is the subject, so
each arrow stops short of its target. No magnitude is encoded.

`signifier-pair` (HMM-10): one surface raised with a shadow line beneath it and
one recessed with a line inside its top edge. `paired-panels` compares the
contents of two panels; this compares two treatments of one control's surface,
which is the affordance claim. Neither surface is a picture of a click.

`feedback-loop` (HMM-11): an input arrow into a system and a return path that
carries the result back to the actor. `goal-gradient`, `decline-curve` and the
other curves run in one direction; no existing shape closes a loop back to its
origin, which is what feedback is.

`proximity-grid` (GES-01): two clusters of identical marks, four by two, with
spacing the only cue. The grid drew a faint rounded rectangle around each
cluster from its first commit. While nothing else in the deck was about
grouping, the frame was harmless annotation; after similarity and common region
arrived it offered a second cue - enclosure - in the drawing whose claim is
spacing, so it was removed. The dots keep their intra-cluster gap of 40 and the
clusters now sit exactly 110 apart, which is what the dashed line measures and
the card says.

The removal also corrected a number that had been wrong since the first commit.
Each cluster's box was drawn 20 pt beyond its dots, so the two clusters sat 130
pt apart while the dashed line measured 110 and the label said 110 - the line
stopped 20 pt short of the lower cluster and pointed at empty paper. Without the
boxes the padding has no purpose, the gap is the 110 the line measures, and the
number on the drawing is now the distance on the page. The deck therefore keeps one enclosure treatment and one only:
the filled surface in the common-region drawing, which belongs to the card whose
claim is that a region creates the group. The proximity grid's frame is gone
rather than replaced, so a reader who has seen the earlier deck loses nothing -
the drawing that had a rectangle has none, and the drawing that argues for
rectangles still has one.

`similarity-columns` (GES-02): four columns, evenly spaced, with circles in the
first and last and squares in the middle two. `proximity-grid` varies distance
and holds form constant; this varies form and holds distance constant, so the
two are complements and neither demonstrates the other's factor. The spacing
was made uniform for that reason: at 70 and 100 pt the columns grouped by
proximity into a different answer than the shapes did, and a drawing whose two
cues disagree demonstrates neither.

`common-region` (GES-03): three identical, equidistant circles and a boundary
around two of them. No other shape draws a boundary, so in this deck enclosure
has no other meaning to confuse it with. The boundary encloses exactly two of
three; the count is legibility, not a measured claim.

`simplest-form` (GES-04): twelve points on a circle, joined once with jitter and
once as a circle. The two panels are two descriptions of the same marks; nothing
else in the deck draws one set of points twice. The jitter is fixed drawing, not
a measured irregularity.

`broken-ring` (GES-05): a whole ring beside one broken into four arcs. The
broken ring is not completed in the drawing; the reader supplies the segments,
which is the claim. No other shape leaves a mark deliberately unfinished.

`shared-edge` (GES-06): one wavy contour divides one field into a filled and an
unfilled region, with no cue saying which region owns the edge. `common-region`
draws a boundary around a group; this draws a boundary that belongs to neither
side, which is the figure/ground relation and not an enclosure claim.

`crossing-curves` (GES-07): two smooth curves crossing once and continuing
through. Nothing else in the deck crosses itself; `intent-gap` breaks a path on

`link-beats-gap` (GES-08): six marks at one spacing, once unlinked and once with
a stroke joining the middle pair across the widest gap. `proximity-grid` and

`shared-motion` (GES-09): a field of still marks and one column carrying the same

marks reads as a link, which is GES-08's claim.

`necker-cube` (GES-11): a wireframe cube whose twelve edges support two
readings. The drawing prefers neither; the caption says there are two. Nothing
else in the deck is deliberately ambiguous, and GES-10 reuses `odd-one-out`

The two keys that were bare identifiers - `hierarchy` and `network` - are quoted
like the other shapes, so a script that enumerates shapes from the source finds
all forty-two. No behaviour changes.


## 38. The year field accepts what a source says; the bounds are typo catchers

`academicOrigin.year` is a signed integer. The schema caps it at 2100 and sets
no floor. Both bounds are typo catchers rather than historical claims: a year
typed with one digit too many lands above the ceiling, and a year typed as
anything but an integer is rejected by the type.

The floor of 1800 that shipped in d66d48d was the same kind of guard, but it was
never documented, and it encoded the range of the sources the deck happened to
have at that moment - Weber (1834) is the oldest - rather than a property of a
source. A later card can cite something older, and then the schema, not the
author, would decide what the record may say. A series-level bound that no one
chose had edited a card's content. It also moved HMM-07 off its origin: Ockham, c. 1320, is the heuristic's origin and the floor made that year
unrecordable, so the record's year is Maeda (2006), the design statement the
card actually makes (see §37). Removing the floor costs nothing that the type
does not already protect: a year is a fact the author records, and a bound that
is a fact about today's corpus will be wrong later, while a bound that catches a
typo stays right.

A negative year means BCE, and **printing a BCE year on a card is undecided and
not implemented**. The citation strings are computed in one place (§25); no card
in this deck needs the case, and adding a helper now would build a control with
nothing to show. The field accepts a signed integer; how a renderer prints one is
a typography decision, not a validation bound. This entry records that the value
is accepted, not a format for it; if a card ever needs one, the format is decided
then and implemented where the strings are built.

## 39. Two source names change because they name a commercial methodology

The second deck's inventory is a list of named tactics, and two of those names
identify a commercial method rather than a public technique: a pitch arc sold
as part of a named sales programme, and a story template usually attributed to
a studio and popularised under its brand. A clean-room repository may describe
the structure, but it should not use a company's name for it as a card title.

The structures are unchanged. They are recorded under the public name for the
same shape:

- **The Story Spine** (source title: "The Pixar Pitch"), attributed to Emma
  Coats, who published the five-clause form as a set of story rules in 2011.
  The attribution is to the person who wrote it down, not to the studio.
- **The Insight-Led Challenge** (source title: "The Challenger Commercial Arc"),
  attributed to Matthew Dixon and Brent Adamson, whose 2011 book describes the
  sequence. The card keeps the sequence and drops the product's name.

Nothing else is renamed. Every other card carries the inventory's name verbatim
and is checked against it, because the list is the artefact: a name quietly
shortened here would be a name a reader could not find in the source.

## 40. A BCE year prints as "335 BCE"

§38 accepted signed years and left the print format undecided, on the grounds
that no card needed it. The second deck cites Aristotle (-335), Horace (-13) and
Sophocles (-429), so the case arrived and the format is now decided: a negative
year prints as its absolute value followed by a space and `BCE`, in every
renderer. A positive year prints unchanged.

The conversion lives in one function (`formatYear`) for the generated markdown
and in the two renderers' own year lines, which cannot import it: the Typst
template and the browser bundle. Each prints `(335 BCE)` for -335 and `(1999)`
for 1999, and the deck test asserts both strings. -1 prints `1 BCE`; there is no
year zero in the conventional calendar, and a record that needs that precision
should carry the year as text rather than as a number.

The blast radius is nine cards, not the three that first prompted this: ARC-04
(-335), ARC-06 (-13), ARC-11 (-429), PRS-01 (-350), PRS-11 (-380), MIC-01
(-750), MIC-05 (-335), MIC-08 (-55) and MIC-11 (-450). Every one of them
printed a negative number before this entry; the helper is the only reason they
do not now.

UX cards are unaffected: none cites a negative year, so the printed artifact's
bytes are unchanged.

## 41. A deck declares the order its cards are read in

`deck.json` may set `printOrder` to `"id"` (the default, and what every deck did
before this existed) or `"family"`, which follows the deck's own category list.
`orderCards` in the core applies it once, and both the printed pages and the web
bundle take their order from there. The alternative - sorting in the print build
alone - is what the second deck had for a day: its book ran Arc, Corporate,
Micro, Persuasion while its bundle and rules ran Arc, Persuasion, Corporate,
Micro, and a reader had no way to know which order the deck intended.

The default keeps the first deck byte-identical, because "id" is the order
`loadCards` already returned. A deck that wants the source's order says so.

## 42. A deck declares what its card backs print

A card's back was a checklist, an anti-pattern and an optional prompt. The next
deck's backs are none of those: voice traits, a lexicon, phrasing to avoid, a
shadow, anchors, an example. None of it is a checklist, and printing it under
that heading would make the label lie.

`deck.json` may now declare `blocks`: an ordered list of `{ field, label,
style }`, where `style` is one of `traits`, `words`, `quotes`, `prose`, `list`
or `example`. `deckBlocks` in the core validates the list - a field name is
required and an unknown style fails loudly - and the print template, the web
viewer and the rules generator each read it instead of hard-coding a face.
`fields.items` and `fields.antiPattern` may be `null`, which names no field;
every renderer then omits that section entirely rather than printing a heading
over nothing.

The default is no blocks. That is what keeps the two shipped decks byte for
byte: with an empty list the print template's block branch renders nothing,
the viewer takes the path it always took, and the rules generator prints the
lines it always printed. Verified by rebuilding both PDFs against their
committed hashes, and every generated web, rules and skill file against its
committed bytes.

A block whose field a record does not carry prints nothing, which is why the
list is shared across records that carry different subsets of it; a block that
is absent needs no per-card flag to say so.

Two flags were added when the first deck to use blocks was built. A block may
set `"card": false`, which keeps it out of the recto and verso, the web card
and the card index while still printing it in the rules file and the skill
resource. The archetype deck uses it for the on-voice example: with six blocks
on the verso the example ran past the safe bottom, and it belongs with the
rules anyway, where a writer reads it next to the voice notes. The type was not
shrunk to make it fit.

The second is strictness, and it lives in the deck rather than the engine. The
engine still treats a missing block as absent, which is right for a list shared
across records. A deck may instead make every block field required in its own
schema; the archetype deck does, and `scripts/test/archetypes.test.mjs` deletes
each declared field in turn and asserts validation fails and names the field.
Empty arrays are treated as absent by the template as well, and the deck's
schema also sets `minItems: 1` on each; either alone would print no heading,
and both together mean a record cannot claim a block and leave it blank.

## 43. The fifth family is named for what the source calls it

The source presents sixteen cards: twelve in Mark and Pearson's four
motivational quadrants of three, then four more under its own heading,
"Campbellian Narrative Dynamic Cards". Its taxonomy matrix labels those four
"Campbellian Dynamic", not a quadrant. This deck keeps that structure as five
families - Order & Stability, Mastery & Risk, Belonging & Connection,
Independence & Fulfillment, Narrative Functions - with three cards in each of
the first four and four in the fifth. Calling the fifth "Narrative Functions"
says in plain words what the source's "dynamic" means: these archetypes are
turns inside a story (a gate, a call, an ambiguity, a companion), not stances a
person or brand takes for a whole piece. The skill says so where it routes a
writer to a family.

The ids are `ARCH-01` to `ARCH-16`, not `ARC-`. The narrative deck already uses
`ARC-01` to `ARC-12` for Arc & Plot, and two decks whose ids differ by one
letter invite a wrong lookup. `scripts/test/archetypes.test.mjs` extracts the
sixteen card headings from the source and checks each id, name and family
against that extraction rather than against a retyped list. The regex captures
each heading's text after its leading "The", so what the test proves is that
names match the extraction modulo the article: the deck's names drop that word
throughout, and do not differ from the source's headings in any other way.

## 44. Every figure parameter changes the drawing

The deck declares sixteen new shapes in `packages/core/svg.js`, one per card,
taking the registry from 49 to 65. Each is a function of its declared
parameters - citadel's tiers, columns, spread and crenellations; the compass's
span, radius, rings and pivot; the aegis's half-width, drop, chevrons and
reach, and so on for all sixteen - and every parameter is read by the drawing.
The acceptance gate proves it by perturbing each parameter in turn (numbers to
`2n+3`, strings gain a character, booleans flip) and comparing the rendered
SVG; a parameter that changes nothing fails the gate for that card. No shape
was declared without parameters, so no exception had to be recorded.

Two tunings came out of looking at the printed pages rather than the gate. The
hexagram's orbit moved from 150 to 132 because a dot crossed the caption, and
the clarion's caption baseline is fixed at y 250 with the record's `steps` at
34 because the caption crossed an arc. Neither needed a new knob: the shape's
existing parameters carried the fix.

## 45. An accent is measured against the paper, not chosen by eye

The five family accents are printed as 6.5 pt and 7 pt text on white, so they
must clear the WCAG normal-text threshold, and the shipped decks already sit
well above it. The archetype deck's accents, with contrast against white
computed by WCAG 2.x relative luminance:

| Family | Accent | Ratio |
|---|---|---|
| Order & Stability | `#1E3A8A` | 10.36:1 |
| Mastery & Risk | `#991B1B` | 8.31:1 |
| Belonging & Connection | `#9F1239` | 8.02:1 |
| Independence & Fulfillment | `#065F46` | 7.68:1 |
| Narrative Functions | `#5B21B6` | 8.98:1 |

The method: linearise each sRGB channel (`c/12.92` below 0.04045, otherwise
`((c+0.055)/1.055)^2.4`), take `L = 0.2126R + 0.7152G + 0.0722B`, and compute
`1.05 / (L + 0.05)`. All five pass AA (4.5:1) and AAA (7:1) for normal text.

A first draft used the source's brighter shades (`#1D4ED8`, `#DC2626`,
`#BE123C`, `#059669`, `#7C3AED`). I reported `#BE123C` as 7.6:1; that figure
was never computed, it was an estimate written as a measurement. The computed
value is 6.29:1, so it passed AA and failed AAA. Worse, `#059669` computes to
3.77:1, below AA for the small text it colours. The whole set was darkened to
the table above, and the correction stands here rather than being edited out.

## 46. The extraction is committed, because the source is not in git

`scripts/test/archetypes.test.mjs` checked the sixteen records against the
source's card headings by reading `SupportingInformation/03 - Archetypes/
Archetype Card Deck Framework.md` and extracting them. That folder is
gitignored (`.gitignore`: the research input stays out of git, §10), so the test
read a file that only exists in a working copy that happens to carry the
research. It passed on every machine that had the input and failed on every
checkout without it.

CI found this and I did not: run 42878987087 on `bf91451` failed at *Tests and
gate* with `ENOENT ... SupportingInformation/03 - Archetypes/...` while the
three per-deck jobs passed and `npm test` passed locally. The local green was
not a weaker test; it was a different tree.

The fix keeps the extraction as the authority without needing the source at
test time. `scripts/extract-source-headings.mjs` extracts the sixteen headings
and writes them to `decks/archetypes/data/source-headings.json`, with the
source's path and sha256 recorded beside them. The test compares the records
against that committed file, always, and where the research input *is* present
it extracts again and requires the two to agree - so on a working copy with the
source, the committed artifact cannot drift from it; on a bare checkout, the
records are still held to a copy taken from the source rather than retyped.

What this does not prove, and does not need to: CI cannot notice that the
research input changed. The input is fixed, read-only and the person's to
version; if it ever changes, rerunning the script is the deliberate act that
records it. Nor is the committed copy an asset from the source: it is sixteen
card headings, the same public names the records already print.

The instrument lesson is the one §45 and the truncation finding already make in
another key: a test that reads an untracked file is testing the machine it runs
on. Any input a test depends on belongs in git, or its absence belongs in the
test as a stated condition.

## 47. The inventory is the deck's data, and the test holds the records to it

The facilitation deck's forty-eight exercises are an inventory before they are
cards: number, name, stage, room, clock, difficulty, deliverable, and whether the
source prints a protocol for the exercise. That inventory is committed at
`decks/facilitation/data/source-inventory.json`, for the reason §46 records: the
research input is gitignored, so anything a test depends on has to be in git.

`scripts/test/facilitation.test.mjs` compares all forty-eight records to it,
field by field, and also checks the 10/10/10/10/8 stage split and that no two
cards draw the same picture. What that proves is exactly what it says: the
records match the committed extraction. It does not prove that the extraction
matches the source, which is a transcription the operator made and this seat can
re-run but cannot independently re-derive without the input.

Two records drifted from the inventory while they were being written, and both
were caught by comparing rather than by reading.

- WS-16 Brainwriting 6-3-5 has a room of `"6"`. The schema said `minLength: 2`,
  a bound nobody chose on purpose, and the author wrote `"Six"` and `"Six people
  · 30–45 min · intermediate"` to satisfy it. The bound encoded a guess about
  what sizes look like; the data says otherwise. `groupSize` and `minutes` now
  bound at the inventory's own longest value, five characters, and WS-16
  carries `"6"`.
- WS-01's deliverable was paraphrased into "A bounded problem statement with the
  user impact and the business cost written down." The inventory says "Bounded
  problem definition with user impact and business context". The record now
  carries the inventory's words.

The lesson is the one §38 records in another form and the schema keeps
repeating: a validation bound is a claim about the world. When the bound and the
data disagree, the bound is the thing to examine.

## 48. A method with no documented originator prints a note, not a blank

Thirty-one of the forty-eight methods are in common use with no single
documented originator - dot voting, fist to five, hopes and fears. Naming an
inventor for them would be an invention. The record's `origin` may therefore
carry a `note` alone: a sentence saying where the method comes from in the
ordinary sense ("Widely used in design practice; no single documented
originator."), printed as the whole source line.

The engine change is small and declarative. `packages/prepress/src/card.typ`
prints the note instead of `Source:` when an origin has a note and no author,
work or publication; `packages/web/app.js` and
`scripts/generate-web-data.mjs` hold the same rule for the viewer and for the
generated index, and `check-web.mjs` compares every index cell to the rendered
card so the three cannot drift. An origin that names an author, a work or a
publication is untouched, which is why the three shipped decks still print what
they printed.

Seventeen cards name a documented originator - the Liberating Structures cards
credit Lipmanowicz and McCandless, MoSCoW credits Dai Clegg, Decider Super-Vote
credits Jake Knapp's *Sprint*, the Lean Canvas Experiment Matrix credits Ash
Maurya, and SMART credits George T. Doran. The rest say plainly that no one is
documented, which is a better attribution than a plausible name.

## 49. The provenance split is a schema enum, not a paragraph

The deck's contract is that every card tells the reader, in words, whether its
steps follow a written protocol in the source or were written for this deck from
the method's public definition. Twenty-four cards are in each half.

The sentence is not free text. `decks/facilitation/data/law-schema.json` carries
the two exact strings as an enum:

    "Source protocol: the steps follow the written script in the source."
    "Steps written for this deck from the method's public definition; the source has no protocol."

An enum does three jobs. It makes the disclosure uniform, so a reader learns to
recognise it rather than interpret a new sentence per card. It makes drift
impossible: a record cannot half-claim a protocol, and a generator cannot
rewrite the claim. And it makes the split checkable, which is why the deck's
test can assert that every card's `sourceProtocol` boolean, its provenance
string and the inventory's `protocol` column agree rather than merely coexist.

The cost is real and is recorded in §52: those two sentences are two or three
lines on every back face, and a back face has a measured budget.

## 50. Five shapes draw how a session moves

The deck declares five new shapes in `packages/core/svg.js`, taking the registry
from 65 to 70. Each draws a property of a facilitated session that the earlier
shapes do not:

- `framing-square` - a square boundary ruled into a survey grid, with one
  measured vector running out of its centre: a problem bounded before work
  begins, and a direction chosen inside it (Alignment & Framing).
- `divergent-fan` - rays of equal length fanning out of one origin across an
  arc, each fainter than the last: options widening before anything is chosen
  (Divergent Ideation).
- `convergent-funnel` - many inlets meeting one point, one inlet carrying the
  weight: narrowing to a choice (Convergent Decision).
- `liberating-rings` - concentric rings with one doorway cut through all of them
  and people placed around the outside: a structure that changes who speaks by
  making entry the move (Liberating Structures).
- `action-steps` - ascending blocks, a line tracing the climb, and a marker on
  the one step the room committed to (Action Planning).

Two of them shipped with a defect that the gate caught and the eye would not
have: `liberating-rings` and `action-steps` emitted two attributes with no space
between them (`stroke-linecap="round"vector-effect=...`), which Typst refuses to
parse. The deck would not build at all until it was fixed. Every parameter of
all five shapes is read by the drawing, proven by the gate's liveness check.

## 51. A live parameter can saturate, so one probe is not proof

The gate proves a figure parameter is live by perturbing it and comparing the
rendered SVG (§44). It used one probe per number, `2n+3`; three facilitation
cards failed with `parameter "chosen" does not affect the drawing` even though
the parameter plainly did.

`convergent-funnel` read `chosen` modulo the number of inlets. WS-22 chose the
third inlet of six, and `2*3+3 = 9` is the third inlet of six again. WS-26 chose
the sixth of nine, and `2*6+3 = 15` is the sixth of nine. WS-27 chose the second
of five, and `2*2+3 = 7` is the second of five. The parameter was live; the
probe was saturated, and the gate reported the probe's blind spot as a defect
in the drawing.

Both ends are fixed. The shape clamps `chosen` to the inlet range instead of
taking it modulo, which is what "the chosen option" means and is also how a
value past the last inlet stops wrapping around to the third. The gate now
probes each number three ways - `2n+3`, `n+1`, `n-1` - and fails only when every
one leaves the drawing identical, which is what a parameter nobody reads does.
A dead parameter still fails; a saturating one no longer fails by accident.
The change affects no shipped drawing: the three earlier decks pass the same
liveness check they passed before, and their PDFs still hash to their baselines.

## 52. A card's back face is a measured budget, not a word count

The first pass at the facilitation deck wrote what the methods needed and did
not ask whether it fitted. It did not: every card's face carries a deliverable,
a figure and an at-a-glance line, and its back carries numbered steps, the
failure, the fix, the provenance sentence and the origin line. At the template's
7 pt that is a real constraint, and Typst does not clip content to the block it
is given - it runs on past the safe inset, through the trim line, and off the
page.

Measured at 100 ppi on the shipped template (page 500 px tall, safe content
bottom at row 468.75, trim line at row 487.5):

| | Before the editorial pass | After |
|---|---|---|
| Versos past the safe inset | 45 of 48 | 0 |
| Versos past the trim line (clipped) | 30 of 48 | 0 |
| Worst true overrun (tall-page probe) | 121 px, 87 pt, ~10.6 lines | 0; all versos end at 438–457 |
| Text per card (steps + failure + fix + provenance) | 693–977 characters | 468–584 |

The fix is editorial, not typographic: the shipped 7 pt type and the layout are
untouched. What a back face holds at this size is about 10–13 body lines, and
the provenance sentence and origin line take 3–4 of those lines before any
steps. In characters that is roughly 480–580 including provenance, not the ~700 the
first brief guessed: the editors measured 700 landing between rows 462 and 495,
past the safe inset in every case.

Two rules kept the cut honest. On the twenty-four cards whose steps follow a
written protocol, no beat was dropped: each card keeps at least the source's own
number of timed beats, in order, with the wording compressed. The check for that
is mechanical - the source's `####` section has a counted number of timed
`Step-by-Step Script` beats, and every protocol card carries at least that many
steps; no protocol card has fewer. On the twenty-four cards with no protocol in
the source, beats were merged, which is what the provenance sentence already
tells a reader they are.

Before this, vertical fit was a hand measurement that `scripts/pdf-check.mjs`
said in as many words it could not make (§37): rendered, looked at, and hoped to
be repeated. `scripts/check-fit.mjs` now renders every face of every deck and
measures the lowest ink row against both lines, and the acceptance gate records
`print: fit`. A face past the trim line fails; a face past the safe inset but
inside the trim is reported as TIGHT rather than failed, because the archetype
deck shipped five faces at row 475 (4.5 pt into the cushion, still 0.125 in
inside the trim) and turning an accepted deck red retroactively was not this
slice's call at the time.

The person has since asked for that cushion back rather than a warning the
release carries. ARCH-06, 07, 13, 15 and 16 were compressed editorially - the
shadow sentence in each, no declared block dropped and no type or layout
touched - and all sixteen archetype cards now end inside the safe inset with
zero TIGHT faces. Republishing the deck moves its baseline on purpose:
`archetypes.pdf` is now sha256 `1bc638d4…`, 293,740 B, replacing `5d34f5a5…` at
293,925 B, byte-identical on rebuild. UX and narrative are clean on both lines.

## 53. A card can carry blocks and ordered steps, and the artifacts print both

The engine grew back-face blocks for the archetype deck, whose cards have no
ordered items, and it already had ordered items for the narrative deck, whose
cards declare no blocks. The generated rules and skill resources branched on
`blocks`: a block deck printed its blocks and nothing else. Facilitation is the
first deck that declares both - numbered steps under a "Run it" heading, then
the failure, the fix and the provenance - and both artifacts silently dropped
the steps: `rules/facilitation-rules.md` listed a deliverable, an at-a-glance
line, two prose blocks and a source, with no run sheet at all, and the skill
resource did the same. The print PDF and the viewer always had the steps; only
the two artifacts an agent reads had lost them, which is the worse half to lose.

The fix is a guard, not a new field. In the block branch, a deck whose `items`
field is declared prints its items before the blocks - numbered when the deck's
item style is `steps`, checkboxes otherwise - in both `rulesMarkdown` and
`resourceMarkdown`. `deckShape` already returns `[]` for a deck with no items
field, so the archetype deck's artifacts are unchanged; the UX and narrative
decks never take the block branch. Regenerating all four decks changed only the
facilitation rules and skill files, byte for byte elsewhere.

`scripts/test/facilitation.test.mjs` now asserts that every card's numbered
steps appear in `rules/facilitation-rules.md` and in its stage's skill resource,
so the omission cannot return without a test failing.
